# 原生 C++ 代码注释设计

## 目标

为 `native/duel_core` 的原生规则与搜索代码增加便于人工审阅的中文注释，使读者能够沿着模块边界、关键结算流程和隐含规则阅读代码，同时不改变任何运行时行为或性能。

## 注释层级

1. 每个主要 `.cpp` 和核心头文件在文件开头说明模块职责、输入输出以及它在完整结算链中的位置。
2. 在大型函数组和关键入口前标出流程阶段，例如目录编译、状态转换、事件发现、效果结算、攻击与进场、回合收尾、状态键和搜索。
3. 只为无法从语法直接看出的规则添加行内说明，重点解释“为什么必须这样做”和必须保持的不变量。

不逐行复述循环、赋值、条件判断或标准容器操作，不为显而易见的 getter、转换器和绑定样板堆叠注释。

## 必须解释的隐含规则

- `NativeState::scalars` 各槽位的稳定含义，以及保留兼容槽位不得挪用。
- 运行时卡牌以 `instance_id` 区分实例，不能依赖视觉顺序或仅凭目录 ID。
- 触发效果在发现与结算之间如何保存来源、目标和区域信息，以及哪些条件需要重新确认。
- `CARD_SUMMONED`、`CARD_AFTER_SUMMONED`、攻击前后、翻面和移除等阶段的先后关系。
- 普通手牌出牌、特殊进场、额外出牌和回合边界之间的计数关系。
- `turn_count` 是从 1 开始的单方回合编号，只有真正关闭一个单方回合才增加。
- 搜索深度按完整单方回合边界计算；同回合计划复用、PV、history 和 TT 的职责边界。
- 搜索与通用规则代码不得识别具体卡牌 ID；目录能力必须先编译为通用原语。
- 热路径中的快速不可能性判断、索引查询和浅复制为什么不能随意替换为全量扫描或深复制。

## 语言与维护原则

注释使用中文，代码标识符、事件名、原语名和日志字段保留英文原名，方便全文搜索。注释描述稳定的职责与规则，不记录临时调试经过、历史争论或容易过期的具体性能数字。

## 验证

- 最终差异除注释外不得改变表达式、控制流、数据布局或绑定接口。
- 运行 `git diff --check` 并人工检查注释覆盖与代码差异。
- 重建 Windows `Release + template_debug` 原生库。
- 运行原生生产规则、模拟器和搜索定向测试；由于没有行为改动，不额外重复完整 78 套测试。
