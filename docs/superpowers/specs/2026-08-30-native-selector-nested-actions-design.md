# 原生选择器、嵌套动作与运行时能力切片设计

日期：2026-08-30

## 目标

扩展测试专用的 C++ 紧凑状态原型，使其能够编译并执行真实卡牌声明中的通用有序
选择器、选择器子动作、改点、内力、非攻击翻面和动态授予能力。目标是提高 14 个
真实 Quick 开局的原生根出牌覆盖率，同时继续以 `DuelSimulator` 为唯一权威规则
实现和逐事件校验基准。

本阶段不把原生路径接入生产搜索、控制器、测试模式或贪心回退，也不允许根据卡牌
ID、名称或门派写分支。所有新能力只通过已有目录声明词汇工作。

当前基线为：14 个不同的真实 Quick 开局共有 490 个合法根出牌，其中 271 个由
原生路径支持并与权威实现完全一致，219 个被安全拒绝。原生探针有 754 项检查；
5,000 次已覆盖普通出牌的最近基准约为权威 GDScript 的 10.50 倍。

## 范围

本阶段新增以下通用能力：

- 递归编译的动作节点；
- `ACTION_FOR_EACH_SELECTED_CARD` 及全部现有选择区域、顺序、数量字段和选择条件；
- 选择器内外的 `ACTION_CHANGE_POWERS`；
- `ACTION_GAIN_KI` 和 `ACTION_SPEND_KI`；
- `ACTION_FLIP_SELF`；
- `ACTION_GRANT_ABILITY_TO_SELF`；
- 已支持的抽牌、引用移除、自我移除、阻止翻面和移除当前能力动作在选择器主体上的
  精确语义；
- 改点批次、内力变化事件和上述动作会抵达的触发条件；
- 动态能力的有序运行时表示、被动去重和主动能力全部替换规则；
- 修正“删除前置能力会令后续已发现触发失效”的无意下标耦合。

本阶段明确不实现：

- 移动或交换位置；
- 临时能力压制及恢复；
- 弃牌批次、弃牌复制或从弃牌区取回；
- 生成牌、按武器过滤抽牌、空牌库生成太祖长拳；
- 返回手牌、召唤、重新进场或变形；
- 额外出牌；
- 嵌套标准攻击或指定攻击；
- `ACTION_IF`；
- 资源转移或循环分配。

未支持的声明只有在当前分支真正抵达时才令整个私有原生分支拒绝。授予一个带有
未来未支持触发的能力本身可以成功；等该未支持部分实际触发时才拒绝。

## 编译结构

`CompiledAction` 从平铺记录改为递归节点。节点保存：

- 动作 opcode；
- 已编译的整数、字符串名、卡牌引用、所属方引用和失败策略参数；
- 可选 `CompiledSelector`；
- 有序子动作数组；
- 可选的不可变授予能力池引用。

本阶段只执行 `ACTION_FOR_EACH_SELECTED_CARD` 这一种容器节点，但递归结构不把
未来 `ACTION_IF` 或其它包装器锁死在新的平铺格式中。编译器仍严格检查声明形状；
不认识的字段、参数类型或子节点编译为明确的 `UNSUPPORTED`，不得近似解释。

动作执行上下文把以下概念分开保存：

- 最初能力来源的实例及其开始结算时的所属方、区域和位置快照；
- 当前动作主体；
- 当前选中牌；
- 触发牌；
- 攻击者；
- 本次攻击中实际翻面的精确实例集合；
- 当前事件、能力和触发器位置，用于事件字段与改点批次 ID。

选择器子动作中的“自己”是当前选中牌；`CARD_REF_ABILITY_SOURCE` 始终是最初
发动能力的牌。`ACTION_REMOVE_THIS_ABILITY` 是例外：它始终删除正在结算的原能力
条目，而不是当前动作主体的任意能力。

## 选择器

### 扫描顺序

选择器严格按声明的 `zones` 顺序扫描，且同一实例只观察一次：

1. `CARD_ZONE_HAND`：先能力来源所属方、再另一方；每方按固定物理手牌槽从左到右。
   `SELECT_ORDER_HAND_RIGHT_TO_LEFT` 只反转各方内部的物理槽顺序，不反转双方顺序。
2. `CARD_ZONE_BOARD`：始终按行优先 `0..8`。
3. `CARD_ZONE_DISCARD`：先来源方、再另一方，保持各自弃牌数组顺序。
4. `CARD_ZONE_REMOVED`：先来源方、再另一方，保持各自移除数组顺序。

选择时锁定精确 `instance_id`。`limit` 在收集到指定数量后停止；
`required_count` 要求最终选择数准确相等，否则整个选择快照为空。两者同时出现时
沿用当前 `DuelCardSelector.snapshot()` 的行为。

### 条件

本阶段一次编译全部现有选择条件：

- `CONDITION_SELECTED_CARD_IS_ALLY`；
- `CONDITION_SELECTED_CARD_IS_ENEMY`；
- `CONDITION_SELECTED_CARD_WEAPON_IS`；
- `CONDITION_SELECTED_CARD_IS_NOT_SOURCE`；
- `CONDITION_SELECTED_CARD_ADJACENT_TO_SOURCE`；
- `CONDITION_SELECTED_CARD_SURROUNDED_BY_ALLIES`；
- `CONDITION_SELECTED_CARD_ORIGINAL_OWNER_IS_SELF`；
- `CONDITION_SELECTED_CARD_ORIGINAL_OWNER_IS_ENEMY`；
- `CONDITION_SELECTED_CARD_FLIPPED_BY_CURRENT_ATTACK`；
- `CONDITION_SELECTED_CARD_POWERS_CAN_CHANGE`；
- `CONDITION_SELECTED_CARD_HAS_NONZERO_POWER`；
- `CONDITION_SELECTED_CARD_IS_PREVIOUS_HAND_PLAY`；
- `CONDITION_SELECTED_CARD_CAN_SPEND_KI`；
- `CONDITION_SELECTED_CARD_CAN_TRANSFER_RESOURCE`。

武器、资源、数量和相对所属方字段在加载时编译为有类型参数。四边全为 `-1` 的牌
不满足可改点或可转移点数资源；“可耗内力”根据目标当前运行时主动能力和已启用
效果门控计算，不根据卡牌 ID 判断。

### 快照与重验

首次扫描只快照匹配实例。每个实例轮到结算前，重新定位该实例，并只重验声明中的
选择条件。选择区域本身不是重验条件：单纯移动或换区不会取消快照；如果声明条件
依赖相邻、所属方、武器、点数或资源，则当前值变化可以令该实例被跳过。

一个实例重验失败时跳过并继续下一个快照实例，不重新扫描棋盘或手牌补选。每个实例
依次完成其全部子动作后，才开始下一实例。若来源已经离场，选择器继续使用能力开始
时保存的来源所属方、区域和位置快照；来源实例处于移除区时不把其当前移除区位置
误认为新的活跃来源。

## 叶子动作

### 改点

`ACTION_CHANGE_POWERS` 支持：

- 非零固定整数；
- 现有 `VALUE_CARD_COUNT` 手中牌数量值，所属方为能力来源或目标当前所属方；
- `CARD_REF_SELECTED_CARD`、`CARD_REF_ABILITY_SOURCE`、
  `CARD_REF_TRIGGER_CARD` 和 `CARD_REF_ATTACKER_CARD`。

目标必须仍是快照中的精确实例。四边全为 `-1` 时无效果；每一边结果最低为零。
成功时先发 `powers_changed`。负向变化令四边全部归零时，随后以
`power_reached_zero` 原因走完整的移除前、真正移除和移除后链。

原生必须生成与权威实现相同的 `power_change_batch_id`。同一个选择器动作内所有
`powers_changed` 及其连带 `card_exiled` 共用一个批次；不同顶层动作默认使用不同
批次；显式 `power_change_batch_group` 继续合并声明指定的逻辑批次。

### 内力

`ACTION_GAIN_KI` 和 `ACTION_SPEND_KI` 支持正整数，以及缺省当前主体或显式上述
卡牌引用。增减成功后立即发 `ki_changed`；扣除不得令内力小于零，否则返回无效果。

每一个 `ki_changed` 都在下一子动作前立即派发 `CARD_KI_CHANGED`。本阶段同步支持
实际会抵达的 `CONDITION_KI_CHANGED_CARD_IS_SELF`、
`CONDITION_KI_REACHED_ZERO` 和既有 `CONDITION_KI_AT_LEAST`。由该事件产生的翻面、
移除、能力变化或未知声明分别走正常生命周期或安全拒绝。

### 非攻击翻面

`ACTION_FLIP_SELF` 作用于当前动作主体，并根据最初能力来源的所属方快照解析
`OWNER_ABILITY_SOURCE` 或 `OWNER_OPPONENT_OF_ABILITY_SOURCE`。目标必须仍在场且
所属方确实需要变化，否则无效果。

成功请求走完整翻面流程：翻面前事件、阻止翻面、所有权改变、普通非保留能力清理、
`CARD_AFTER_FLIPPED`、延迟的自身翻面后能力清理。现有保留能力与四边点数规则不变。

### 授予能力

`ACTION_GRANT_ABILITY_TO_SELF` 作用于当前主体，可作用于场上或手牌中的精确实例。
授予内容在根状态加载时递归编译进共享不可变能力池。

- 获得结构完全相同的被动能力时无效果；
- 获得新的被动能力时，保留当前全部能力并追加该能力；
- 卡牌可以先天拥有多个主动能力，按目录数组顺序提供；
- 动态获得一个主动能力时，删除当前所有带 `activation` 的能力条目，保留所有被动
  能力，再把新主动能力追加到末尾；
- 只有能力数组实际变化时才发 `ability_gained`。

授予的能力可以含有本阶段未知的未来触发、动作或修饰。其原始规范化声明仍保存在
不可变池中，输出时不得丢字段；只有未知部分真正影响当前事件、攻击或回合边界时才
拒绝分支。

### 已有动作的主体扩展

以下已支持动作继续沿用原语义，但可在选择器中把当前主体或
`CARD_REF_SELECTED_CARD` 作为目标：

- 固定数量、无过滤且不需要空牌库生成的 `ACTION_DRAW_CARDS`；
- `ACTION_EXILE_CARD`；
- `ACTION_EXILE_SELF`；
- `ACTION_PREVENT_TRIGGER_FLIP`；
- `ACTION_REMOVE_THIS_ABILITY`。

抽牌接收方使用动作主体开始该动作列表时的所属方快照。因此选择器内先移除当前牌、
再抽牌，仍由该牌移除前的当前所属方抽牌。

### 失败策略

每个支持动作编译 `on_invalid_context`。普通无效动作返回 `NO_EFFECT` 并继续；声明
`STOP_RULE` 的无效动作把当前规则标记为 `INVALID_CONTEXT`，停止其剩余动作。此前
已经合法完成的动作不回滚，这与权威执行器一致。

`STOP_RULE` 与“原生不支持”不同。抵达未知 opcode、字段、事件副作用或运行时功能时，
整个出牌私有副本被抛弃，返回 `supported = false`、`valid = false`，且不暴露 payload、
事件、翻面或移除的部分结果。

## 运行时能力表示

原生内部把每张牌的当前能力表示为有序的 `RuntimeAbilityEntry` 数组。每个条目引用
一个全局不可变的编译能力与原始规范化声明；相同内容共享池条目，但数组位置和顺序
仍保留。加载根状态时从 `active_ability_set_pool` 建立该数组，分支复制只复制紧凑
引用数组，共享不可变池。

获得、失去、主动能力替换和翻面清理会真实修改有序条目数组，不再以只关闭 bitmap、
输出时才压缩的方式模拟删除。这样后续能力顺序、能力计数、修饰优先级和状态键都与
权威数组一致。

输出完整紧凑 payload 时，把每张牌当前有序能力声明重新驻留到物化的
`active_ability_set_pool`，并写回对应 set index。校验和包含当前能力池引用的有序
序列；共享池内容保持不可变。恢复出的 `DuelState`、`state_version` 和规范状态键必须
与权威结果完全相同。

## 已发现触发不因其它能力换位而取消

当前 GDScript 触发器在发现时记录能力数组下标，并要求结算时同一下标仍是相同内容。
这会使“前面的另一项能力被删除”意外取消仍然存在的后续能力，没有玩法依据。

本阶段把权威实现与原生实现统一改为以下规则：

1. 发现触发时快照来源实例、所属方、位置、能力条目、触发器位置和事件上下文。
2. 能力条目在当前事件窗口内拥有不写入卡牌声明、存档或规范状态键的临时运行时句柄。
3. 对能力数组进行授予、删除或清理时，未被删除条目的句柄随条目保留；新获得或恢复的
   条目获得新句柄。
4. 结算前在来源牌当前能力数组中按句柄重新定位。删除其它能力导致位置变化不取消
   该触发。
5. 来源牌不再位于要求的位置、所属方改变、效果门控关闭、该能力本身已失去或触发
   条件重验失败时，仍然取消该组。
6. `ACTION_REMOVE_THIS_ABILITY` 删除重新定位到的当前条目。

触发组同时保留“发现时能力下标”和“结算时当前下标”。发现时下标继续用于
`power_change_batch_id` 等既有事件身份，确保能力换位不会改写已经建立的事件编号；
当前下标只用于重验和删除准确的运行时条目。

GDScript 可通过保留未变能力 Dictionary 的引用身份来承载事件窗口句柄；原生使用
分支局部的轻量整数句柄。句柄只需在一次同步事件结算链中稳定，不跨出牌边界序列化，
也不改变“能力声明没有 ID”的目录规则。结构相同的动态被动能力仍按既有规则去重。
由于能力声明内容从不在运行时修改，权威能力数组的增删和替换应保留所有未变条目的
引用身份；恢复或新授予的条目使用新引用，不能继承已经失去能力的待结算触发。

## 验证

### 权威规则回归

为 `DuelTriggers` 增加最小回归：同一事件发现两个不同能力，前一个结算时删除位于
它之前或自身的其它能力，后一个能力虽然数组位置改变，仍按原快照结算；若后一个
能力本身被删除，则其触发取消。`ACTION_REMOVE_THIS_ABILITY` 必须删除重新定位后的
正确条目。

### 原生聚焦探针

增加与 `DuelSimulator` 逐事件对照的合成状态，覆盖：

- 四个区域的扫描顺序、手牌物理槽与反向顺序；
- 去重、`limit`、`required_count`；
- 选择后移动或换区仍可重验，条件失败时跳过且不补选；
- 来源离场后的来源快照；
- 当前主体、选中牌、能力来源、触发牌和攻击者引用互不混淆；
- 每个目标完成全部子动作后再处理下一目标；
- 固定与手牌计数改点、批次 ID、归零移除、四边全 `-1`；
- 增减内力、余额不足、逐次 `CARD_KI_CHANGED` 连锁；
- 非攻击翻面、阻止翻面、保留与延迟能力清理；
- 被动授予去重、多个先天主动能力、动态主动能力全部替换；
- 授予含未知未来规则的能力，并只在未知规则实际抵达时拒绝；
- 前置能力删除后后续触发换位但继续结算；
- `NO_EFFECT`、`STOP_RULE` 与整分支 `UNSUPPORTED` 的区别；
- 拒绝结果没有部分 payload、事件、翻面或移除。

### 真实 Quick 覆盖

继续使用完全相同的 14 个真实 Quick 开局，枚举全部 490 个合法根出牌。完成标准：

- 原生支持数必须高于当前 271；
- 每个受支持分支的有效性、完整恢复状态、规范状态键、`state_version`、captures、
  exiles 和逐项事件与 `DuelSimulator` 完全相同；
- accepted mismatch 必须为零；
- 剩余拒绝按原因重新统计，便于选择下一通用切片。

### 性能与仓库验证

重新运行原生构建和紧凑状态探针，报告普通已覆盖出牌与新增复杂声明路径的耗时、
相对 GDScript 倍率及分支复制吞吐。由于本阶段实际执行更多规则，不设置任意的 3%
淘汰线；但必须记录任何回退并排查异常数量级下降。

随后运行 `git diff --check` 和完整仓库测试套件。若需要可见实机走查，使用 Dummy
音频或静音总线，不改变玩家正常音频默认值。

## 非目标与采用门槛

- 不把原生模块接入生产路径；
- 不宣称原生已经能够搜索完整真实对局；
- 不改卡牌中文描述、数值、图片、奖励或解锁规则；
- 不以卡牌 ID 或名称判断能力；
- 不为提高覆盖率近似执行未支持规则；
- 不以支持数上升代替逐状态、逐事件精确一致；
- Windows 和未来 Android 打包、完整回合边界及生产搜索采用仍是后续独立阶段。
