# 挥剑自宫战败保底设计

日期：2026-08-14

## 卡牌定义

- `KuiHua0`（挥剑自宫）的 `tier` 从 5 改为 6。
- 卡牌目录为它声明战败保底条件，而奖励系统不直接检查具名卡牌 ID。
- 声明包含：最低角色阶级为 5，以及玩家必须已解锁至少一张 `effect_gate = self_castration` 的卡牌。
- 6阶牌名沿用牌库现有的其他等级深红色，不新增颜色规则。

## 触发条件

创建战败奖励时，某张声明了战败保底的卡牌必须同时满足：

1. 玩家当前角色阶级至少为声明值；
2. 玩家已解锁至少一张具有声明所需 `effect_gate` 的卡牌；
3. 保底牌自身尚未解锁；
4. 保底牌本轮尚未展示过。

胜利奖励不使用这条保底。玩家未达到5阶时，挥剑自宫不会通过普通或保底战败奖励出现。

## 奖励抽样

- 满足条件的挥剑自宫强制占据本次战败奖励的一个位置。
- 其余位置从原有战败候选池随机抽取，排除已经强制加入的卡牌，最多补足三张。
- 最终奖励顺序再次随机打乱，因此挥剑自宫没有固定位置。
- 如果普通候选不足两张，仍保证挥剑自宫出现，但沿用现有“最多三张”的规则，不创建重复或无效候选。
- 已存在的待领取奖励继续原样恢复，不重新抽取或追加保底牌。

## 每轮仅展示一次

- 存档新增本轮已展示保底奖励的卡牌 ID 列表，并随 schema 迁移与校验。
- 创建并成功保存含挥剑自宫的奖励时，原子地将它记为本轮已展示。
- 玩家选择其他奖励后，该记录仍保留，因此挥剑自宫在本轮后续战败奖励中不再出现。
- 只有真正进入奖励三选一才算展示；条件不足或奖励创建失败不写入记录。
- 开始新流程、闭关重修、完成流程或清除全部进度时清空本轮记录。重开后若再次满足条件，挥剑自宫可以再次出现。

## 通用目录声明

目录字段采用通用结构，例如：

```gdscript
"guaranteed_defeat_reward": {
    "min_character_tier": 5,
    "requires_unlocked_effect_gate": EFFECT_GATE_SELF_CASTRATION,
}
```

卡牌目录校验拒绝未知字段、无效阶级与未知效果门槛。奖励逻辑按目录顺序处理符合条件的声明；当前只有挥剑自宫使用该声明。

## 验证

- 卡牌目录确认挥剑自宫为6阶并接受合法保底声明。
- 1至4阶战败不提供挥剑自宫。
- 5阶但没有已解锁需自宫牌时不提供挥剑自宫。
- 5阶、已解锁需自宫牌且未解锁挥剑自宫时，首次战败奖励必含挥剑自宫。
- 选择其他牌后，本轮后续战败不再提供挥剑自宫。
- 闭关重修并开始新流程后可以再次触发。
- 已解锁挥剑自宫时不再触发。
- 胜利奖励及普通战败候选等级规则保持不变。
- 固定随机种子验证其他候选与最终位置仍可重复测试。
- 运行完整测试套件：`powershell -ExecutionPolicy Bypass -File tools/run_tests.ps1`。
