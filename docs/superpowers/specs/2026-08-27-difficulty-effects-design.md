# 进阶效果设计

日期：2026-08-27

## 目标

在现有难度 0 至 9 的选择、解锁和持久化机制上实装逐级累积的闯关与对局规则。
这些规则必须由生产模拟路径统一结算，使真人对局、测试模式、贪心后备 AI、深度
搜索和回放共享同一份状态与时机。难度零继续保留现有门派选择默认提示；用户说明
中括号内的敌人数解释不进入游戏文案。

## 集中式规则声明

新增纯数据规则模块 `scripts/difficulty_rules.gd`，把难度限制到 `0..9` 后提供以下
累计结果。调用方读取规则结果，不重复散写难度阈值：

```gdscript
const EFFECT_TEXTS: Array[String] = [
	"",
	"可挑战一派宗师",
	"可挑战武林神话",
	"后行动时，友方只占据一个八卦方位",
	"先行动时，敌方占据的八卦方位点数加二",
	"卡组总品阶低于对手时方可选择先攻",
	"后行动时，友方不占据八卦方位",
	"先行动时，敌方占据的八卦方位点数再加二",
	"敌方手牌数首次变为一时，其抽一张牌",
	"对局开始时，随机一张敌方手牌点数加一",
]

static func victories_required(difficulty: int) -> int:
	if difficulty <= 0:
		return 13
	if difficulty == 1:
		return 14
	return 15

static func later_player_bagua_count(difficulty: int) -> int:
	if difficulty >= 6:
		return 0
	if difficulty >= 3:
		return 1
	return 2

static func later_enemy_bagua_power(difficulty: int) -> int:
	if difficulty >= 7:
		return 4
	if difficulty >= 4:
		return 2
	return 0

static func player_must_be_strictly_lower_to_go_first(difficulty: int) -> bool:
	return difficulty >= 5

static func enemy_draws_on_first_one_card_hand(difficulty: int) -> bool:
	return difficulty >= 8

static func buff_random_enemy_opening_hand_card(difficulty: int) -> bool:
	return difficulty >= 9
```

函数名可以在实施时按现有命名习惯微调，但声明的输入、输出与阈值不能改变。
进阶六覆盖进阶三的八卦数量；进阶七在进阶四的基础上把同一静态加值从二累计
到四。其它规则均随难度向上保留。

## 闯关长度

生产流程当前最多有 15 个敌人。当前轮次的最终胜利阈值改为：

- 难度 0：击败第 13 名敌人后通关；
- 难度 1：击败第 14 名敌人后通关；
- 难度 2 至 9：击败第 15 名敌人后通关。

因此难度 0 不会进入第 14、15 名敌人的对局，难度 1 不会进入第 15 名敌人的
对局。现有 `MainFlowController.victories_required` 测试覆盖入口继续保留：有效阈值
取配置值和难度阈值中的较小值，使使用 `victories_required = 1` 的流程测试仍能
构造一战通关，而生产默认值 15 得到上述 13、14、15 的结果。

最终胜利仍由 `DeckProfileStore.record_completed_duel_and_save()` 的原子事务
决定。奖励、解锁下一难度、卡牌清理、最高分和结局摘要沿用现有流程，只改变
何时进入最终胜利分支。

## 门派选择提示

难度 0 的底部默认提示保持：

```text
轻触门派查看详情，长按门派并拖至下方
```

难度 1 至 9 把原有占位文本替换成当前一级新增效果，不拼接此前累计效果：

```text
进阶一：可挑战一派宗师
进阶二：可挑战武林神话
进阶三：后行动时，友方只占据一个八卦方位
进阶四：先行动时，敌方占据的八卦方位点数加二
进阶五：卡组总品阶低于对手时方可选择先攻
进阶六：后行动时，友方不占据八卦方位
进阶七：先行动时，敌方占据的八卦方位点数再加二
进阶八：敌方手牌数首次变为一时，其抽一张牌
进阶九：对局开始时，随机一张敌方手牌点数加一
```

顶部 `江湖门派-进阶n`、汉字数字、临时提示覆盖、箭头交互和即时保存均保持
现状。难度 0 的“十三个敌人”和用户说明中的其它括号文本不显示。

## 先攻限制

组牌界面继续比较玩家与当前敌人的卡组总品阶：

- 难度 0 至 4：玩家总品阶不高于敌方即可选择先攻；
- 难度 5 至 9：玩家总品阶必须严格低于敌方才能选择先攻。

选择后攻始终合法。难度 5 以上的阻止提示使用
`卡组总品阶低于对手时方可选择先攻`；低难度保留现有“不高于”提示。
控制器从活动存档读取 `run_difficulty`，但合法性计算调用集中规则模块，不修改
卡组总品阶算法。

## 初始八卦方位

`DuelOpeningSetup` 继续负责构造纯初始棋盘。它接收开场行动方、活动难度和
随机数生成器，并根据玩家相对于敌人的先后手生成：

### 玩家后行动

- 难度 0 至 2：沿用现状，在 12 组正交相邻位置中等概率选择一组，生成两张
  玩家所属的普通 `BaGuaFangWei`；
- 难度 3 至 5：只生成一张玩家所属的普通 `BaGuaFangWei`，九个格子等概率；
- 难度 6 至 9：不生成玩家所属的 `BaGuaFangWei`。

### 玩家先行动

敌方作为后行动方始终获得两张相邻 `BaGuaFangWei`，位置仍在 12 组正交相邻
组合中等概率选择：

- 难度 0 至 3：四边保持目录初值 0；
- 难度 4 至 6：两张牌的四边在初始状态中均为 2；
- 难度 7 至 9：两张牌的四边在初始状态中均为 4。

所有八卦仍是初始场面，不是进场：不发出 `card_placed`、`card_summoned`、
进场触发、标准攻击或 `powers_changed`，也不播放任何动画。进入对局画面时直接
显示最终数量、位置和点数。

## 进阶八：敌方一张手牌时抽牌

### 状态

`DuelState` 增加本局纯数据标记，表示进阶八的一次性机会是否已经消耗。该字段
必须被深拷贝、回放快照和 `DuelStateKey` 编码；不能只存在于控制器。活动难度
也必须进入对局状态或等价的不可变规则状态，并参与搜索键，保证相同棋盘但不同
进阶规则不会错误共用置换表结果。

### 触发边界

模拟器集中观察敌方手牌的每次实际原子变更。某次变更完成后，若：

1. 当前难度至少为 8；
2. 本局机会尚未消耗；
3. 敌方当前手牌数恰好为 1；

则先永久消耗机会，再为敌方按正常抽牌规则抽一张。

“变为一”不限定减少方向：只要一次真实手牌变更完成后数量从非一变为一即可，
包括 `0 -> 1`。对局初始手牌本身不算一次变更。一次机会消耗后，即使抽牌效果
因未来规则未能增加手牌，也不会再次触发，避免递归和反复尝试。

批量弃牌保持现有原子语义：所有锁定目标先一起离开手牌，再进入各自弃牌后与
批量完成时点。因此 `3 -> 0` 不经过可观察的一张手牌状态，不触发；`2 -> 1`
会在该批次手牌变更完成后立即触发。

### 抽牌与事件

触发抽牌复用普通 `ACTION_DRAW_CARDS` 的单张抽取规则，包括牌库为空时的现有
太祖长拳兜底、手牌槽位、隐藏信息和 `card_drawn` 事件。它不是
`card_added_to_hand`，不额外公开敌方手牌。事件在导致手牌变为一的原始变更
事件之后出现，控制器沿用现有抽牌表现。

观察入口必须覆盖所有通用手牌突变原语：正常出牌、从手牌移除或移除区移动、
单张与批量弃牌、从手牌直接进场、抽牌、返回手牌以及效果创建手牌。不得在搜索
或模拟器中按具体卡牌 ID 判断。

## 进阶九：随机强化敌方起始手牌

对局初始双方手牌和牌库完成构造、洗牌与运行时实例化后，且初始回放快照创建
之前，执行一次纯初始状态修正：

1. 收集敌方起始手牌中允许改变点数的牌；
2. 四边均为 `-1` 的牌不合法，沿用现有 `Rules.can_change_powers()` 判定；
3. 在所有合法实例中等概率选择一张；
4. 把该实例上、右、下、左四边各加 1。

若没有合法实例则不生效，也不顺延到牌库。修改保留同一个 `instance_id`，不改变
卡牌目录定义、内力、能力、所属方、可见性或手牌槽位。它不发出
`powers_changed`、能力触发或动画；隐藏敌方手牌不会泄漏被强化的目标。

随机选择使用独立的开场难度随机流或独立种子，避免启用进阶九后改变八卦相邻
组合的概率与既有确定性测试。初始快照保存强化后的状态，因此实战和回放一致。

## 数据流与组件边界

### `DifficultyRules`

只保存难度到规则结果和提示文案的纯映射，不读取存档、不创建场景节点，也不
修改对局状态。

### `DeckProfileStore` 与 `MainFlowController`

存档层继续拥有 `run_difficulty`。流程控制器读取一次活动难度，并把它传给组牌
和对局构造；最终胜利事务使用同一难度计算有效敌人数阈值。难度解锁、重置和
迁移结构不升级 schema，因为本次没有新增持久化字段。

### `DuelOpeningSetup`

只创建初始棋盘和开场手牌静态修正所需的纯数据。随机结果由调用方提供的 RNG
决定；不产生转场事件。

### `DuelSimulator`、`DuelState` 与搜索

模拟器拥有进阶八的一次性触发与普通抽牌结算。状态保存活动难度和机会消耗位，
复制与搜索键完整编码。搜索仍只读取通用难度状态、手牌和动作，不检查命名卡牌。

### 控制器

`DeckBuilderController` 只根据纯规则结果启用先攻按钮和选择提示。
`DuelController` 只传入活动难度、建立初始状态并播放模拟器事件；不独立决定
抽牌、目标或点数。

## 错误与边界处理

- 缺失或越界的活动难度限制到 `0..9`；合法活动存档仍由现有校验保证不会越过
  全局已解锁难度。
- 测试模式不绕过进阶效果；它只改变解锁和双方操控/可见性。测试可显式设置难度。
- 八卦位置选择没有空位冲突，因为它发生在空棋盘构造阶段。
- 进阶九没有合法手牌时静默不生效，不选择四边 `-1` 的牌，也不改选牌库。
- 进阶八先写入已消耗标记再请求抽牌，避免抽牌引起的嵌套手牌观察再次触发。
- 回放不重新随机八卦或进阶九目标，而是使用已记录的初始状态。

## 自动化验证

### 集中规则与流程

- 难度 0、1、2、9 分别得到 13、14、15、15 的敌人数阈值；
- 生产默认阈值按难度缩短，测试覆盖值 1 仍可一战通关；
- 难度 0/1 在第 13/14 战结束，难度 2 在第 15 战结束；
- 通关后的奖励绕过、难度解锁、最高分与重置行为保持现状；
- 难度 1 至 9 的提示精确匹配设计文本，难度 0 不显示敌人数说明。

### 组牌与先攻

- 难度 4 时相等总品阶仍可先攻；
- 难度 5 时相等总品阶不可先攻，严格较低时可先攻；
- 后攻不受影响，阻止提示随难度使用准确措辞。

### 初始场面

- 难度 0 至 2 的玩家后手仍获得两张相邻普通八卦；
- 难度 3 至 5 的玩家后手只获得一张，九格都可被种子覆盖且分布均匀；
- 难度 6 至 9 的玩家后手不获得八卦；
- 玩家先手时敌方始终获得两张相邻八卦，难度 3/4/6/7 的四边分别为
  `0/2/2/4`；
- 初始构造不产生进场、攻击、加点或移除事件。

### 进阶八

- 难度 7 不触发，难度 8、9 触发；
- 敌方 `2 -> 1` 后抽一张并产生普通 `card_drawn`；
- 同局第二次变为一不再抽；
- 批量 `3 -> 0` 不触发，批量 `2 -> 1` 触发一次；
- `0 -> 1` 的真实手牌加入也触发，初始一张手牌不触发；
- 牌库为空时沿用普通抽牌兜底；
- 状态复制、回放和搜索键保留难度及已消耗位。

### 进阶九

- 难度 8 不强化，难度 9 只强化一张敌方起始手牌；
- 被选牌四边各加一，实例 ID 和其它运行时字段不变；
- 四边 `-1` 永不被选中；首个候选非法时仍可选择后续合法实例；
- 全部非法时不生效；
- 固定种子得到固定目标，随机流不改变八卦位置结果；
- 不产生点数动画事件，回放起始状态与实战一致。

## 手动验证与完整回归

实现完成后运行：

```powershell
powershell -ExecutionPolicy Bypass -File tools/run_tests.ps1
```

并在 540×960 竖屏实际检查至少难度 0、3、5、7、8、9：

- 门派选择提示与箭头切换正确；
- 相等品阶在难度 4/5 的先攻按钮状态不同；
- 先后手开场八卦数量和点数直接显示为最终值且没有动画；
- 进阶八抽牌动画只出现一次；
- 进阶九不在开场泄漏隐藏敌方手牌，回放初始状态一致。

## 非目标

- 不改变敌人目录、敌人卡组内容、AI评价权重、奖励池或计分公式；
- 不在结局或对局顶部新增难度标签；
- 不为初始八卦或进阶九强化添加动画；
- 不把全局进阶规则声明成命名卡牌能力；
- 不修改现有难度解锁、上次选择、当前轮次和分难度最高分的存档结构。
