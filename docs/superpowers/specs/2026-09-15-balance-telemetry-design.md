# 通关对战平衡数据采集设计

## 目标

玩家真正通关一轮游戏时，自动上传该轮每一场已经完成的对局摘要，供后续分析
敌人强度、卡组表现和胜负分布。采集只服务于平衡分析，不进入战斗规则、AI
搜索或玩家进度存档。

首版后端使用腾讯云 CloudBase 上海地域的 HTTP 云函数和文档型数据库，以提高
中国大陆玩家的连接可靠性。Cloudflare Worker、D1 和 Resend 均不进入首版。

## 采集范围

每场完成的对局记录以下内容：

- 敌人的稳定目录 ID；
- 玩家当时的等级；
- 玩家和敌人各自带入本场的五张主卡组，按固定手牌槽顺序保存卡牌 ID；
- 哪一方先行动；
- 胜利或失败结果。

整轮报告额外记录：

- 随机生成的匿名玩家 ID；
- 唯一 `report_id`；
- 报告格式版本、游戏版本和平台；
- 本轮难度、玩家门派、最终分数；
- 正式胜场和败场总数；
- 客户端辅助时间和服务端接收时间。

不记录副卡组、牌库顺序、具体行动、回放日志、设备标识、账号、邮箱、昵称、
IP 地址或 User-Agent。云函数不主动把请求正文写入日志。

华山进阶零序章中的爱护师弟·令狐冲和江湖武师同样属于本次通关经历，因此
照常记录。失败后的重试是新的已完成对局，也逐场保留。放弃一场尚未完成的
对局、回放和悔棋都不产生额外记录。

## 匿名身份

`BalanceTelemetryStore` 首次运行时生成一个随机匿名玩家 ID，之后独立持久化。
它不由硬件、系统账号、邮箱或游戏进度推导。通关、闭关重修和封剑归隐不会
改变它；卸载应用、清除应用数据，或未来提供明确的重置入口时才会变化。

该 ID 只用于分辨多份报告是否大致来自同一安装，不能用于识别自然人。

## 本地生命周期

新增独立的 `BalanceTelemetryStore`，不把遥测队列塞进
`DeckProfileStore`。其原子写入文件包含：

- `schema_version`；
- `anonymous_player_id`；
- `active_run`；
- `pending_reports`。

文件使用临时文件替换和备份恢复，避免写入中断后同时损坏主文件与备份。

新一轮游戏创建时开始一个新的 `active_run`。为了避免迁移时虚构旧轮次数据，
更新前已经进行中的轮次不追溯采集；只有更新后新建的轮次才设置遥测轮次标记。

真正创建一场对局的初始状态后，从权威的五个固定手牌槽快照双方主卡组，并
保存本场尚未完成的临时记录。对局产生最终胜负后才把它追加到
`active_run.duels`。应用在对局中崩溃时，该场没有结果，不计入报告；重开后
重新进行并完成的对局才记录。

只有击败本轮最后一名敌人、进入正常通关结局时，才把 `active_run` 封装为具有
唯一 `report_id` 的待上传报告。闭关重修、封剑归隐、主动重开或在通关前结束
轮次会清除 `active_run`，不会上传不完整轮次。

封装后的报告写入 `pending_reports`，再异步尝试上传。只有服务端明确返回已保存
或相同 `report_id` 已存在，客户端才删除本地副本。断网、超时、服务器错误和
应用退出都保留完整报告，并在以后进入主菜单的空闲阶段重试。队列不设置静默
丢弃上限。

永久格式错误同样保留原报告并写入本地诊断，但不在同一次启动中频繁重试。

## 启用边界

只有正常导出的 Windows 和 Android 版本允许连接真实地址。以下环境强制关闭：

- Godot 编辑器自动进入的 testing mode；
- 自动化测试；
- AI 基准和命令行夹具；
- 未配置正式 CloudBase 地址的开发构建。

集中使用 `telemetry_enabled` 门控，不在各个场景散落判断。首版导出构建默认
启用；正式上架商店前再在同一门控前增加隐私说明和玩家同意界面，不需要重写
采集链路。

Android 导出需要启用普通网络访问权限。上传只在通关收尾或主菜单空闲阶段
进行，不阻塞画面切换，也不触碰原生 C++ 规则、AI 状态键或搜索热路径。

## CloudBase 接口与存储

### 上传接口

云函数公开一个版本化 HTTP 入口：

```text
POST /v1/reports
```

客户端发送一份完整通关报告。云函数依次检查：

- JSON 与报告版本合法；
- 字段类型、字符串长度、难度和结果枚举合法；
- 每场恰好包含双方各五个卡牌 ID；
- 对局数量和正文总大小处于合理安全范围；
- `report_id` 与匿名 ID 格式合法。

客户端无法安全保存共享密钥，因此上传接口不使用伪装成秘密的内置 token。
保护手段为严格白名单校验、请求体大小限制、CloudBase 网关限流，以及
`report_id` 唯一去重。重复提交返回成功语义而不重复写入。

### 文档模型

集合 `run_reports` 中，一次通关对应一个 JSON 文档，文档键使用
`report_id`。每个文档保存轮次元数据和有序的 `duels` 数组。按一场拆成一个
文档会把普通 12–15 场通关的数据库写入放大十几倍，因此首版明确不采用拆表
方案。

正常报告预计约 10–20 KB，远低于数据库单次 16 MB 出包限制。服务端仍设置较
保守的正文上限来阻断滥用。若一份合法但异常漫长的轮次超过上限，客户端保留
原报告并显示在诊断中，不得截断对局或谎报上传成功；需要时再以版本化分块协议
扩展，而不是在首版预先增加复杂度。

服务端接收时间是统计排序的权威时间；客户端时间只用于辅助排查离线积压。

### 管理导出

云函数另提供管理端导出入口：

```text
GET /v1/admin/export?format=csv&from=YYYY-MM-DD&to=YYYY-MM-DD
GET /v1/admin/export?format=json&from=YYYY-MM-DD&to=YYYY-MM-DD
```

管理接口必须校验仅保存在 CloudBase 服务端环境变量中的管理 Bearer token。
下载脚本从本机环境变量读取 token，仓库不保存任何密钥：

```powershell
powershell -File tools/download_balance_reports.ps1 -Format Csv
powershell -File tools/download_balance_reports.ps1 -Format Json
```

CSV 每场对局一行，重复轮次元数据，并展开为固定的
`player_card_1..5` 与 `enemy_card_1..5` 列，方便直接用 Excel 分析。JSON 保持
轮次下嵌套对局的原始结构。两种格式均支持日期增量下载。

下载脚本默认只读，不会删除云端数据。归档确认后的清理必须使用单独的显式管理
操作，避免误删尚未备份的报告。

## 用量预估与归档策略

一次单文档报告约消耗一次云函数调用、一次数据库写入和少量函数计算，估算为
约 `0.024–0.030` 资源点。免费环境每月 3000 资源点时，上传本身可支持约
五万至七万份月度报告；考虑导出、删除和长期容量后，应在明显更低的数量级留出
余量。

文档型数据库容量按日计费，长期不清理最终会比上传调用更昂贵。因此运营流程
为：

1. 按月增量下载 CSV 与 JSON；
2. 校验本地文件完整且保有至少一份备份；
3. 显式删除已经归档的旧月份；
4. 云端常态只保留最近一至三个月。

早期测试和小规模上架预计远低于免费额度。达到每月数万份通关报告时，先根据
CloudBase 实际资源点账单校正估算，再决定缩短云端留存或升级个人版。

## 代码职责

- `BalanceTelemetryStore`：匿名 ID、本轮暂存、待上传队列、原子保存与重试状态；
- `MainFlowController`：在现有权威流程边界通知轮次开始、对局初始化、对局结果
  和真正通关，不复制进度规则；
- `DuelController` / `DuelReplayRecord`：继续提供已经存在的初始双方五张主手牌
  快照，不持有上传策略；
- `BalanceTelemetryUploader`：异步 HTTP、响应分类和重试调度；
- CloudBase 云函数：服务端校验、去重写入和受保护导出；
- `DeckProfileStore`：保持玩家进度职责，不保存遥测正文。

卡牌规则、`DuelSimulator`、原生 C++ 内核和 AI 搜索均不读取遥测状态。

## 错误处理

- 网络不可用、DNS、超时、HTTP 429 和 5xx：保留报告，下次空闲重试；
- 相同 `report_id`：服务端返回幂等成功，客户端删除本地副本；
- HTTP 4xx 格式错误：保留报告与诊断，本次启动不再热重试；
- 本地文件损坏：尝试备份恢复；主文件和备份都不可用时生成新的匿名 ID，并把
  故障写入本地诊断；
- CloudBase 地址未配置：不发请求，待上传报告继续保留；
- 上传失败永远不影响通关、奖励、存档或退出游戏。

## 验证

实现至少覆盖：

1. 匿名 ID 在多次启动、通关和轮次重置后保持稳定；
2. 新轮开始并逐场完成时，准确保存双方五个槽位和胜负顺序；
3. 失败重试分别记录，放弃、回放、悔棋和崩溃中的未完成对局不记录；
4. 只有正常最终通关封装报告，闭关重修、归隐和提前重开清除未完成轮次；
5. 老版本正在进行的轮次不会被追溯上传；
6. 队列跨启动持久化，临时失败不删除，成功与重复确认后才删除；
7. testing mode、自动测试和 AI 基准不会访问网络；
8. 云函数拒绝缺字段、错误卡牌数量、超大正文和非法枚举；
9. 相同 `report_id` 重复提交只生成一个数据库文档；
10. CSV 固定展开十张主卡组，JSON 保持嵌套结构，日期筛选正确；
11. 未提供或错误管理 token 无法导出；
12. Android Release 具有网络权限，并在大陆移动网络和 Wi-Fi 上各完成一次真实
    通关报告上传与后台读取验证。

先在独立的 CloudBase 测试环境完成真实端到端验证，再把正式环境地址写入导出
配置。不得用编辑器测试直接污染正式平衡数据。
