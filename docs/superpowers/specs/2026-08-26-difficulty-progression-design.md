# 难度进阶机制设计

日期：2026-08-26

## 目标

为每一轮闯关增加独立难度，并建立最高到难度 9 的全局、顺序解锁进度。难度在门派选择场景中切换并立即持久化；本次只实现存档、迁移、选择界面和通关解锁，不添加任何实际战斗加成或敌人修正。

## 核心概念

存档新增三个彼此独立的整数字段：

- `max_unlocked_difficulty`：全局最高已解锁难度，范围为 `0..9`。
- `last_selected_difficulty`：门派选择界面上次选中的难度，范围为 `0..max_unlocked_difficulty`。
- `run_difficulty`：当前活动闯关实际生效的难度，范围为 `0..max_unlocked_difficulty`；没有活动闯关时必须为 `0`。

三者不可互相推导。最高解锁难度是长期进度；上次选择是跨场景、跨进程保存的界面偏好；当前轮次难度是活动闯关的一部分。

## 新存档与迁移

存档模式版本从 9 升到 10。

全新存档的三个难度字段均为 `0`，因此只能选择难度 0。

旧存档迁移时：

- `max_unlocked_difficulty = 2`；
- `last_selected_difficulty = 2`；
- 若现有迁移逻辑能够保留该活动闯关，则 `run_difficulty = 2`；
- 若存档没有活动闯关，则 `run_difficulty = 0`；
- 对于因缺少可重建历史而被现有迁移逻辑关闭的早期活动存档，仍保持关闭，故 `run_difficulty = 0`，但最高解锁和上次选择仍为 2。

校验和修复必须确保所有字段为整数，满足：

```text
0 <= run_difficulty <= max_unlocked_difficulty <= 9
0 <= last_selected_difficulty <= max_unlocked_difficulty
```

非活动存档还必须满足 `run_difficulty == 0`。修复时把数值限制到合法范围，并以修复后的最高解锁难度限制其余两个字段。

## 开始、通关与重置

开始新一轮闯关时，门派选择控制器把当前选中难度传给存档层。存档层重新验证该难度在 `0..max_unlocked_difficulty` 内，并把它写入 `run_difficulty`。UI 不是权限边界，越权难度必须保存失败。

普通胜利、失败、奖励领取、界面切换、退出游戏和重新进入都不改变当前轮次难度。

通关难度 `n` 时，先读取活动轮次的 `run_difficulty`，再令：

```text
max_unlocked_difficulty = max(
    max_unlocked_difficulty,
    min(run_difficulty + 1, 9)
)
```

难度 9 通关后保持封顶。完成解锁后再执行现有通关重置。

重置语义：

- 通关：清除 `run_difficulty`，保留最高解锁难度和上次选择。
- 闭关重修：清除 `run_difficulty`，保留最高解锁难度和上次选择。
- 封剑归隐：使用全新默认存档，三个字段全部重置为 0。
- 测试模式的临时全卡解锁不改变任何难度字段。

通关摘要和计分公式本次不增加难度信息。

## 门派选择界面

### 箭头

在门派选择卷轴左右两侧各增加一个 `TextureButton`，共用用户提供的 `res://inkpics/arrow.png`：

- 右侧使用原图；
- 左侧水平翻转；
- 两者垂直居中贴近卷轴左右边缘；
- 随现有竖屏核心布局重新定位并保持图片比例；
- 当 `max_unlocked_difficulty == 0` 时，两者隐藏且不接收输入；
- 查看详情或拖牌期间禁止按钮输入，避免交互状态冲突。

### 循环选择

存在多个可选难度时：

- 右箭头按 `0, 1, ..., max, 0` 循环；
- 左箭头按相反方向循环；
- 每次按下先请求存档层原子保存新的 `last_selected_difficulty`；
- 保存成功后才更新当前选择和界面文本；
- 保存失败时保留旧选择并显示“保存失败”。

每次进入门派选择场景，都从存档加载 `last_selected_difficulty`，包括退出游戏后重新打开。

### 文本

难度 0 完全维持当前文本：

- 顶部敌人名字使用当前实际的 `upcoming_enemy_name`；
- 底部默认提示为“轻触门派查看详情，长按门派并拖至下方”。

难度 1 至 9 使用汉字数字“一”至“九”：

- 顶部敌人名字为 `江湖门派-进阶n`；
- 底部默认提示为 `进阶n：进阶特效文本占位`。

这里的“进阶特效文本占位”是本次要求显示的固定字面文本，不是未完成的规格占位符。

门派锁定、查看详情、保存失败等临时状态可以覆盖底部默认提示。临时状态结束后，恢复当前难度对应的默认提示。

## 数据与组件边界

### `DeckProfileStore`

负责：

- 难度字段默认值、校验、修复和模式迁移；
- 难度访问器；
- 原子保存上次选择难度；
- 开始闯关时验证并记录当前轮次难度；
- 通关时解锁下一难度；
- 各类重置对难度字段的保留或清除。

在 `begin_run_and_save()` 的现有参数列表末尾增加 `difficulty: int = 0`，以保留现有调用点和测试夹具的难度 0 行为。

### `SectSelectionController`

负责：

- 读取最高解锁和上次选择；
- 箭头显隐、循环输入、立即保存与文本刷新；
- 把当前选择传给 `begin_run_and_save()`；
- 调试访问器，供集成测试读取当前难度、箭头状态和文本。

它不负责决定难度是否合法，也不向战斗规则施加效果。

### 场景与布局

`scenes/sect_selection.tscn` 声明左右箭头按钮和图片资源。`SectSelectionController._layout_scene()` 在现有 `SelectionShell.apply_core_layout()` 完成后，以卷轴当前矩形为基准摆放按钮，避免复制整套响应式布局。

### 其它系统

`MainFlowController`、敌人目录、组牌、AI、`DuelSimulator` 和对局状态本次不消费难度值。未来进阶效果应另行设计，不在本规格中预留空的战斗分支。

## 错误处理

- 难度选择保存失败：保持旧难度与旧文本，底部显示“保存失败”。
- 开始闯关时难度越权或存档无效：沿用开始失败流程，不创建活动闯关。
- 已损坏难度字段：加载修复时限制到合法整数范围；若整体存档仍不合法，沿用现有默认存档兜底。
- 图片缺失或场景节点错误由现有 Godot 资源加载和场景测试暴露，不增加静默替代资源。

## 自动化测试

### 存档与迁移

- 全新存档三个难度字段均为 0。
- 版本 9 的活动和非活动存档迁移到正确的难度字段。
- 更早期、会被关闭的活动存档仍保持关闭且当前难度为 0。
- 非整数、负数、超过 9、超过最高解锁或与活动状态矛盾的数据得到预期修复或校验失败。
- 测试模式临时卡牌解锁保留难度字段。

### 闯关生命周期

- 开始难度 0 和已解锁难度成功写入 `run_difficulty`。
- 未解锁难度不能开始闯关。
- 普通胜负和奖励流程保留当前难度。
- 闭关重修清除当前难度，保留最高解锁和上次选择。
- 通关难度 `n` 解锁 `n+1`，同时完成现有卡牌进度重置。
- 通关难度 9 保持上限 9。
- 封剑归隐把三个字段全部恢复为 0。

### 门派选择集成

- 只有难度 0 时两个箭头隐藏。
- 解锁多个难度后箭头显示，右增左减并在两端循环。
- 左箭头正确水平翻转，右箭头不翻转，共用 `arrow.png`。
- 每次按箭头立即保存，重新创建场景后恢复上次选择。
- 难度 0 使用现有顶部和底部文本。
- 难度 1 至 9 使用准确汉字数字和固定占位提示。
- 检查、拖动、锁定和保存失败等临时提示结束后恢复当前难度默认提示。
- 确认门派后，当前选择成为活动轮次难度。
