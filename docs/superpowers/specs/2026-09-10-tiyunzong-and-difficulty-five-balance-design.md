# 梯云纵四与进阶五平衡调整设计

## 目标

本次调整包含两项相互独立的规则变更：

1. 梯云纵四只响应由其友方所具有的效果造成的移除，不再按被移除牌所在区域判断。
2. 进阶五取消先攻卡组总品阶的额外限制，改为降低战败随机奖励的最高品阶。

两项变更都沿用现有权威路径：卡牌效果由 `DuelSimulator` 的原生内核结算，
奖励资格由 `DeckProfileStore` 生成，难度阈值与提示文字由 `DifficultyRules` 统一提供。

## 梯云纵四

### 玩家可见规则

梯云纵四的第一项效果改为：

> 当任意牌因为我的友方具有的效果所移除时，你抽一张牌。

“友方”相对于该张梯云纵四在触发结算时的新所属方判断。“造成移除的效果来源方”
在该次效果开始结算时确定；来源牌随后移动、翻面或离场，不会改写这次移除的归因。

以下情况满足条件：

- 友方效果令自身移除；
- 友方效果直接移除任意阵营的牌；
- 友方效果降低任意牌的点数，使其四边归零并因此移除。

没有有效效果来源方的系统性移除不满足条件。由敌方效果造成的移除也不满足条件，
即使被移除的是友方牌。

多张梯云纵四按现有全场触发顺序分别结算，每张各抽一张牌。

### 触发时点

继续使用现有的 `CARD_BEFORE_EXILED`。抽牌在待移除牌真正进入移除区之前完成。
如果后续的被移除前效果移动了目标或以其它方式取消原移除，已经完成的抽牌不回滚。

### 通用事件数据

原生移除生命周期在建立 `CARD_BEFORE_EXILED` 上下文时，额外保存这次移除的
效果来源方。该值来自当前动作上下文中已经确定的能力来源方，而不是在触发时重新
查找来源牌的位置或当前阵营，因此来源牌先离场或翻面不会改变归因。

没有能力效果来源的移除将该值保存为无效所有者。该字段只存在于一次结算的事件
上下文中，不写入 `DuelState`，不进入存档、回放快照、状态键或置换表。

新增通用条件：

```gdscript
const CONDITION_EXILE_EFFECT_SOURCE_IS_ALLY: StringName = (
    &"exile_effect_source_is_ally"
)
```

条件在 `CARD_BEFORE_EXILED` 中比较：

```text
本次移除的效果来源方 == 当前触发能力来源牌的所属方
```

无有效效果来源方时条件为假。条件不检查被移除牌的区域、阵营、原始所有者或
是否最终成功进入移除区。

### 完整目录原语声明

梯云纵四新的抽牌能力完整声明为：

```gdscript
const TIYUNZONG_DRAW_ON_ALLY_EFFECT_EXILE: Dictionary = {
    "triggers": [{
        "event": CARD_BEFORE_EXILED,
        "conditions": [{
            "type": CONDITION_EXILE_EFFECT_SOURCE_IS_ALLY,
        }],
        "actions": [{
            "type": ACTION_DRAW_CARDS,
            "amount": 1,
        }],
    }],
}
```

其余两项能力保持不变，`TiYunZong4` 的完整能力数组及顺序为：

```gdscript
"abilities": [
    TIYUNZONG_DRAW_ON_ALLY_EFFECT_EXILE,
    TIYUNZONG_LOCKED_FLIP_MOVE,
    TIYUNZONG_RESUMMON_ACTIVATION,
]
```

旧条件 `CONDITION_TRIGGER_CARD_OUTSIDE_SOURCE_OWNER_HAND` 若目录中已无其它使用者，
同步从已知条件、原生 opcode、编译器和执行器中删除；不得保留无卡牌使用的原语。

### 性能约束

本次只给已经发生的移除事件增加一个整数来源方快照与一次整数比较，不增加事件
发现范围，也不扫描手牌、弃牌堆或移除区。预计不会形成可测的搜索热路径回退；
如果实测出现稳定回退，必须按仓库规则立即报告。

## 进阶五

### 玩家可见规则

进阶五提示文字改为：

> 战败后获得的卡牌品阶降低

原进阶五效果“卡组总品阶低于对手时方可选择先攻”完全取消。所有难度均恢复并
沿用基础先攻规则：玩家卡组总品阶不高于对手时，可以选择先攻。

### 战败奖励品阶

普通战败随机奖励的合法品阶范围为：

```text
进阶零至进阶四：1 ～ 当前角色品阶
进阶五至进阶九：1 ～ max(1, 当前角色品阶 - 1)
```

因此：

- 进阶五以前，战败奖励可以随机到当前品阶；
- 进阶五及以后，二阶以上角色的普通战败奖励不包含当前品阶；
- 一阶始终作为保底：一阶角色在任何难度仍可获得一阶普通战败奖励；
- 已解锁卡牌仍不进入奖励候选；
- 胜利奖励规则完全不变。

`KuiHua0` 等目录声明的保证战败奖励继续通过独立保证池插入，不受普通随机池的
品阶上限限制，其每轮只出现一次、最低角色品阶和效果门控规则保持不变。

### 规则归属与数据流

`DifficultyRules` 新增一个纯函数，接收难度和当前角色品阶，返回普通战败奖励的
最高允许品阶。它负责进阶五阈值与一阶保底：

```text
get_max_defeat_reward_tier(difficulty, character_tier)
    difficulty < 5  -> max(1, character_tier)
    difficulty >= 5 -> max(1, character_tier - 1)
```

`DeckProfileStore.create_reward_offer_and_save()` 读取当前运行难度和角色品阶，
调用该函数构造普通战败候选。它不直接硬编码进阶五阈值。保证奖励候选继续在普通
候选之后由现有专用函数生成，再沿用当前合并、洗牌、保存和本轮已展示记录流程。

`DeckBuilderController` 删除进阶五的严格低于分支与专用提示，先攻合法性统一使用
基础的“不高于”比较。`DifficultyRules.player_must_be_strictly_lower_to_go_first()`
若不再有调用者则删除，不保留失效接口。

本次不修改存档结构。当前运行难度继续从已有 `run_difficulty` 字段读取，旧存档
无需迁移。

## 测试

### 梯云纵四

- 目录测试断言新条件已注册、旧条件无使用时已删除，并核对完整能力数组顺序。
- 友方直接移除敌方牌：抽一张。
- 友方自我移除：抽一张。
- 友方减点令任意牌四边归零：抽一张。
- 敌方效果移除友方牌：不抽。
- 没有效果来源方的移除：不抽。
- 被移除前效果取消原移除：梯云纵四已经抽牌。
- 多张梯云纵四：按触发顺序每张各抽一张。

### 进阶五与奖励

- 进阶四的二至五阶角色：普通战败候选可包含当前品阶。
- 进阶五的二至五阶角色：普通战败候选不包含当前品阶，只包含较低品阶。
- 进阶五及以上的一阶角色：仍有一阶保底候选。
- 进阶五的保证战败奖励：即使高于普通上限，满足原门控时仍能插入。
- 进阶五的胜利奖励：保持当前品阶规则。
- 所有难度在卡组总品阶相等时都允许选择先攻，超过对手时都禁止先攻。
- 进阶五的门派选择提示显示新文本。

实施后先运行梯云纵、难度、奖励存档和组牌界面聚焦测试，再运行完整测试套件。
