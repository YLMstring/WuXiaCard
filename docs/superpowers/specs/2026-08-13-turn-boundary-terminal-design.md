# 回合边界终局判定设计

## 目标

所有终局条件统一在当前玩家或敌人的完整回合结束后、下一方回合开始前判定。达到行动数上限不会截断当前回合。

## 规则时点

一次行动成功后，模拟器仍先增加 `turn_count`。当 `turn_count >= max_turns` 时，只表示本回合应在关闭时结束对局：

1. 当前行动的全部效果正常结算。
2. 当前方已经获得的额外出牌继续执行。每张额外出牌仍各计一次行动，因此最终 `turn_count` 可以超过 `max_turns`。
3. 会授予额外出牌的本方回合结束能力照常结算；由此获得的额外出牌也继续执行，直到本方回合真正关闭。
4. 本方回合结束能力只按现有规则触发一次。
5. 临时能力等回合期状态按现有顺序恢复。
6. 模拟器在切换 `active_player` 和触发下一方回合开始能力之前检查终局。
7. 若终局成立，不切换行动方，也不触发紫霞功等下一回合开始能力；控制器在现有行动表现完成后计分并显示胜负。
8. 若终局不成立，才切换行动方并结算其回合开始能力。

## 其他终局条件

满场仍先结算现有的“对局结束前”触发。触发完成后，若场地仍满，则在同一个回合边界终局点结束；若效果打开了空位，则继续检查其他终局条件，全部不成立时才开始下一回合。

双方均无合法行动等其他终局原因也使用同一边界。待结算效果队列继续沿用现有规则；行动上限在回合关闭前不得因为待处理效果或额外出牌而提前终局。

## 架构

终局规则仍由 `DuelSimulator` 权威决定。`DuelController` 只在完整 transition 的事件表现结束后调用终局查询、统计场上归属牌数并展示结果。AI、测试模式、普通对局和回放因而共享同一行为。

模拟器需要显式表达“已经抵达安全的回合边界”，避免仅凭 `turn_count >= max_turns` 在额外出牌链中报告终局。该数据属于纯状态，不包含任何表现对象。

## 测试

回归测试至少覆盖：

- 达到行动上限后，本方回合结束能力已经结算，但下一方回合开始能力不结算。
- 达到上限时已有额外出牌，模拟器不在链中报告终局；额外出牌完成后才终局，且计数可以超过上限。
- 回合结束能力授予的额外出牌同样可以在上限后完成，且回合结束能力不重复触发。
- 未达到任何终局条件时，下一方回合开始能力仍正常触发。
- 满场的“对局结束前”能力仍先于统一终局检查执行。
