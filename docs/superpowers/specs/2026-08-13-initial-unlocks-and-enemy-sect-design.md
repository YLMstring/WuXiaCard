# 初始解锁与敌人门派解锁设计

日期：2026-08-13

## 目标

- 正常模式的新档只预先解锁太祖长拳与一阶吐纳术。
- 选择门派开始旅程时，解锁该门派全部一阶牌，并从其余锁定的一阶牌中随机解锁三张。
- 初始牌组固定为太祖长拳、一阶吐纳术和本次随机解锁的三张牌；其余已解锁牌进入牌库。
- testing mode 在本次运行中临时解锁全部卡牌，但绝不污染正常存档。
- 敌人目录可以声明所属门派；玩家击败该敌人时解锁对应门派。

## 正常模式初始流程

`DeckProfileStore.create_default_profile()` 创建未开始旅程的新档。此时：

- `unlocked_card_ids` 只包含 `TaiZuChangQuan` 与 `TuNaShu1`。
- `main_deck` 暂时只包含这两张牌。
- 牌库不包含任何锁定牌。
- 默认开放门派仍为华山派。

玩家在门派选择界面确认门派时，存档层原子地完成开局初始化：

1. 解锁所选门派全部一阶牌。
2. 从尚未解锁的全部一阶牌中随机选取三张并解锁。
3. 将主牌组设置为太祖长拳、吐纳术1和这三张随机牌。
4. 所选门派的其他一阶牌按现有解锁顺序进入牌库。
5. 保存旅程状态和首个敌人。

随机数生成器作为可选参数传入存档层；生产环境随机化，测试使用固定种子。若不足三张合法候选，则使用全部剩余候选；当前卡池应始终足够。

## Testing mode

testing mode 使用运行时临时存档路径。进入测试主流程时，从正常存档复制进度数据，在临时副本中解锁所有卡牌并整理牌库；所有测试模式下的牌组交换、奖励和进度写入临时副本。

正常存档文件不会被修改。进程结束或切回正常模式后，临时解锁不可见。testing mode 仍需保留五张主牌组约束；已有五张主牌不变，不足五张时才按目录顺序补足。

## 敌人门派声明

敌人定义可选填：

```gdscript
"sect_id": &"HuaShanPai"
```

- 缺省表示击败该敌人不解锁门派。
- 声明值必须是 `SectCatalog` 中存在的 `StringName`。
- 胜利结算读取本次被击败敌人的定义，在生成奖励前把相应门派加入 `unlocked_sect_ids`。
- 失败、放弃和仅开始战斗不解锁门派。
- 最终胜利同样先应用门派解锁，再关闭本轮旅程。
- 重复击败同门派敌人是幂等操作。
- 本次只提供声明与结算机制，不给现有敌人擅自分配门派。

## 数据与兼容性

- 不提升存档 schema；现有字段已足以表达新的卡牌和门派解锁集合。
- 旧存档保持现有解锁，不因加载或修复而重新随机。
- “封剑归隐”创建新的默认档，因此恢复新的两张基础牌开局。
- “闭关重修”结束当前旅程并保留已经解锁的门派、熟练度和最高分，但不保留卡牌解锁进度。
- “闭关重修”后的卡牌集合与新档相同：只解锁太祖长拳和吐纳术1，主牌组暂时只有这两张牌；下次选择门派时重新解锁该门派一阶牌并随机解锁三张一阶牌。

## 验证

- 默认档仅解锁两张基础牌。
- 固定随机种子下，选门派准确解锁该门派一阶牌和三张额外一阶牌，并形成规定的五张主牌。
- 随机三张不得包含基础牌、所选门派已解锁牌、非一阶牌或重复牌。
- testing mode 可见全部卡牌，退出后正常存档字节内容保持不变。
- 合法、缺省、非法敌人门派声明均有目录测试。
- 胜利解锁门派；失败、放弃路径不解锁；最终胜利仍解锁。
- 闭关重修保留已解锁门派、熟练度和最高分，清除其他卡牌解锁并恢复两张基础牌。
- 改动完成后运行完整 `tools/run_tests.ps1`。
