# 原生置换表设计

日期：2026-09-04

## 背景

`DuelNativeCompactKernel` 是唯一生产规则与深度搜索实现。2026-09-04 对最新四个额外出牌压力开局进行十秒 `self_turn` 探测时，460,706 个访问节点中有 333,262 个节点命中了此前已经返回的相同“完整原生局面＋剩余回合边界”，可复用率为 72.34%。其中叶节点为 73.74%，内部节点仍达到 60.88%。这说明缓存不仅能省去叶点评估，也有机会跳过完整子树。

当前只有默认关闭的机会统计集合，没有任何评分或边界复用。本阶段新增真正的有界原生置换表，并用严格等价测试和相同四开局的容量消融决定是否保持生产默认。

## 目标

- 在原生 alpha-beta 搜索中安全复用已完成节点的评分或边界。
- 保持固定深度搜索的评分与规范动作选择不变。
- 保留同回合 principal line，使深度二额外出牌计划不因缓存命中而丢失。
- 桌面与 Android 生产默认都使用固定 8 MiB 上限。
- 表的内存不会随对局数、搜索节点数或游戏时长增长。
- 超时、取消或规则失败不得污染置换表。
- 搜索仍完全与卡牌 ID、名称和具体卡牌规则无关。

## 非目标

- 不跨两次独立 AI 思考共享表。
- 不把更深条目用于回答不同剩余深度的请求。
- 不实现开局库、永久学习或跨对局缓存。
- 不改变局面评估函数、搜索深度定义、PV 或 History 规则。
- 不承诺重复率等同于最终提速比例。

## 生产配置

公共生产入口 `DuelSearch.find_best_action_iterative()` 在调用者未声明时设置：

- `use_transposition_table = true`
- `transposition_table_mib = 8`

桌面和 Android 使用相同默认值。直接原生测试入口保持置换表默认关闭，便于等价和消融测试。显式 `use_transposition_table = false` 必须完全绕过分配、哈希查询和条目维护。容量为零也视为关闭。

容量消融支持 4、8、16、32 MiB，但这些数值不成为额外生产配置档位。

## 表结构与内存生命周期

使用固定容量、两路组相联的连续数组，不使用会动态增长的 `unordered_map`。

- 根据请求字节数和实际 `sizeof(TranspositionEntry)` 计算可容纳条目数。
- 组数向下取不超过容量的二次幂，每组两个槽位，以掩码完成索引。
- 分配只发生在一次根搜索开始时；所有迭代加深层共享同一张表。
- 根搜索结束后数组一次释放。没有静态表、全局表或跨搜索残留。
- 每个完成的公开深度递增 generation，用于冲突替换，不用于正确性判断。

八 MiB 是严格上限；对齐和辅助对象也必须计入实现说明。若无法分配，搜索应安全退化为关闭置换表并在诊断字段中报告，而不能使本次决策失败。

## 键与条目

精确键由以下两部分共同决定：

1. 当前完整 `NativeState` 的 64 位校验值；
2. 当前节点剩余的 `owner_turn_boundaries`。

剩余深度是键的一部分，因此不同搜索视野不会互相替代。根玩家在一次根搜索内固定，不必写入键。现有校验值包含运行时实例、所有权、区域顺序、点数、内力、能力、压制、揭示和回合标量等权威状态。

每个条目保存：

- 完整 64 位精确键；
- 评分；
- `EXACT`、`LOWER` 或 `UPPER` 边界类型；
- 剩余回合边界数；
- generation；
- 本子树是否触及搜索视野边界；
- 是否存在最佳动作；
- 最佳动作的紧凑字段：动作类型、来源索引、目标种类、目标索引和主动能力索引。

紧凑动作不保存 `StringName`。从精确状态恢复时，根据手牌索引或场上格子重新取得当前实例 ID，再与当前合法动作匹配。只有匹配成功的动作才能参与排序或 principal line 恢复。

## 查询规则

节点进入后、生成合法动作前查询两个槽位：

- 键不完全相同：未命中。
- `EXACT`：直接返回评分，并传播条目的视野边界标记。
- `LOWER`：`alpha = max(alpha, score)`。
- `UPPER`：`beta = min(beta, score)`。
- 边界更新后若 `alpha >= beta`，直接返回缓存边界并记为置换截断。
- 边界不足以截断时继续正常搜索；若缓存动作仍合法，将它放在现有 PV 之后、结构排序之前。

最终动作优先级为：

`本轮 PV > 置换表动作 > 结构排序 > History > canonical`

缓存动作只改变访问顺序，不改变同分时的 canonical 选择规则。

命中 `EXACT` 且条目带有合法最佳动作时，将该动作写入当前 iteration 的 `principal_actions` 和排序提示，使同回合额外出牌计划仍可被恢复。叶节点可以没有最佳动作。

## 写入与边界分类

进入节点时保存调用者传入的原始 `alpha` 与 `beta`。节点正常完成后按最终评分分类：

- `score <= original_alpha`：`UPPER`
- `score >= original_beta`：`LOWER`
- 其它：`EXACT`

终局、视野边界和无合法动作叶节点写入 `EXACT`。因 alpha-beta 截断而正常返回的节点可以写入 `LOWER` 或 `UPPER`。以下情况绝不写入：

- 截止时间到达；
- 用户取消；
- 节点限制中断且不受最小深度保护；
- 原生规则不支持或转移失败；
- 子节点未正常返回。

条目同时保存该子树是否触及视野边界。缓存命中必须把此标记传播到当前迭代，防止错误地把有深度截断的局面标记为 `solved`。

## 冲突与替换

同一组的替换顺序如下：

1. 使用空槽；
2. 精确键相同时，以新条目更新旧条目；
3. 否则优先淘汰更老 generation 的条目；
4. generation 相同则优先淘汰剩余深度较小的条目；
5. 深度相同则优先保留 `EXACT`；
6. 完全同级时固定淘汰第一个槽位，保持确定性。

完整键不相同的哈希碰撞只能导致覆盖或未命中，不能复用评分。

## 诊断字段

普通生产搜索不启用高频统计。`collect_search_diagnostics = true` 时至少报告：

- 表容量、条目大小和实际槽位数；
- probes、hits、exact hits、bound hits；
- exact returns、bound cutoffs；
- stores、updates、replacements、collisions；
- cached move queries、legal hits、illegal hits；
- leaf/internal probes 与 hits；
- allocation fallback；
- 当前旧机会统计，以便比较“看见重复”和“真正复用”。

计数不得参与搜索决策。

## 正确性验证

新增原生聚焦测试覆盖：

- 置换表关闭时所有新字段为零且不分配。
- `EXACT`、`LOWER`、`UPPER` 的查询和截断语义。
- 相同局面不同剩余深度不命中。
- 两路冲突、确定性替换及完整键校验。
- 缓存动作重新验证；失效动作不用于排序或 principal line。
- 超时、取消和失败节点不写入。
- 缓存视野标记正确传播。
- 固定深度关闭/开启时，真实开局与派生局面的评分和 canonical 根动作一致。
- 迭代加深关闭/开启时，已完成深度结果合法，且未完成更深层不覆盖已发布结果。

随后运行完整标准套件，并构建 Windows Release 原生库和 Android ARM64 Release 原生库。

## 性能验证

使用最新四个 `extra_play_cap` 开局、十秒 `self_turn`、当前生产 PV＋History 排序：

1. 关闭置换表，关闭高频诊断，记录速度、深度、动作和评分。
2. 分别以 4、8、16、32 MiB 重复同一赛程，仍关闭高频诊断。
3. 单独用生产候选容量开启诊断，记录真实命中、截断、替换和内部节点收益。
4. 比较每局而非只比较总吞吐，特别关注原本只能完成深度一的两局。

生产候选必须满足：

- 所有固定深度等价测试通过；
- 四局没有非法动作、原生拒绝或 fallback；
- 8 MiB 相比关闭状态没有稳定性能倒退；
- 若 4、16 或 32 MiB 明显优于 8 MiB，只报告证据并再次征求用户同意，不自动改变生产默认。
