# 分难度历史最高分设计

日期：2026-08-27

## 目标

把当前“每个门派一个历史最高分”扩展为“每个门派在难度 0 至 9
分别保存历史最高分”。通关较高难度时，同一成绩同时提升该门派所有较低
难度的最高分。难度 0 和难度 1 的本局最终得分及历史最高分均封顶为
500；难度 2 至 9 沿用现有计分公式且不增加新上限。

门派选择界面查看门派时，难度 0 继续显示 `最高分：xxx`；难度 1 至 9
改为显示当前难度的汉字名称和对应最高分，例如 `进阶二：yyy`。

## 存档结构与版本

存档模式版本从 10 升到 11。`best_scores_by_sect` 保留现有字段名，但值从
单个整数改为按难度嵌套的字典：

```gdscript
{
    "HuaShanPai": {
        "0": 500,
        "1": 500,
        "2": 1200,
        "3": 1200,
    },
}
```

JSON 对象键统一使用字符串。门派键必须对应当前门派目录中的合法 ID；难度键
必须是十进制字符串 `"0"` 至 `"9"`；成绩必须是非负整数。没有保存的门派或
难度等价于最高分 0，不强制为全部门派预先写满十个键。

`DeckProfileStore` 新增按“门派 ID + 难度”读取单个成绩的接口。门派选择界面
只调用该接口，不直接理解嵌套存档结构。需要整份成绩数据的测试或维护代码仍可
通过深拷贝访问器读取，不能获得存档内部的可变引用。

## Schema 10 迁移

Schema 10 及更早、但已经带有 `best_scores_by_sect` 的存档，原有每门派单个
最高分同时迁移到难度 0、1、2：

- 难度 0：`min(旧最高分, 500)`；
- 难度 1：`min(旧最高分, 500)`；
- 难度 2：完整保留旧最高分；
- 难度 3 至 9：不生成成绩，读取时视为 0。

例如旧最高分 4321 迁移为 `{ "0": 500, "1": 500, "2": 4321 }`。
旧存档原有的难度解锁、上次选择和活动轮次迁移规则保持不变。没有旧成绩的
门派不生成空记录。

## 校验与修复

当前 schema 的严格校验要求：

- 外层和每个门派的成绩集合都是字典；
- 门派 ID 存在于门派目录；
- 难度键是 `"0"` 至 `"9"` 中的一个；
- 成绩是非负整数；
- 难度 0、1 的成绩不超过 500。

修复流程保留所有合法的门派、难度和整数成绩；非法门派、非法难度键、非整数
或负数成绩被忽略。难度 0、1 的有效非负整数即使超过上限，也会被压到 500，
避免旧数据或局部损坏导致低难度最高分越界。缺失记录继续按 0 读取。

不对不同难度的已有成绩强制建立大小顺序。向下同步是新通关记录的写入规则，
而不是加载时重写玩家历史数据的理由。

## 最终得分

通关时仍由 `DeckProfileStore` 的最终胜利事务生成结局摘要。先按现有公式计算：

```text
原始分 = floor(15000 / effective_duel_count)
```

随后按当前活动轮次的 `run_difficulty` 得到本局最终得分：

```text
难度 0 或 1：最终分 = min(原始分, 500)
难度 2 至 9：最终分 = 原始分
```

结局摘要中的 `score` 直接保存最终分，因此结局界面在难度 0、1 最多显示 500，
不会先显示原始分再仅限制历史记录。现有有效对局计数、无败判断和敌人历史均
不改变。

## 最高分写入与向下同步

最终胜利事务在清除活动轮次之前读取当前门派、当前难度和本局最终分。它更新
当前难度以及所有更低难度，不更新任何更高难度。每个目标难度独立计算可记录
成绩：

```text
候选分(d) = min(本局最终分, 500)  当 d 为 0 或 1
候选分(d) = 本局最终分            当 d 为 2 至当前难度
最高分(d) = max(原最高分(d), 候选分(d))
```

例如难度 4 获得 1200 分后，该门派难度 0、1 最多提升到 500，难度 2、3、4
最多提升到 1200，难度 5 至 9 完全不变。若原最高分更高，则任何记录都不会
下降。

成绩始终按门派隔离。完成一个门派的闯关不会读写其它门派的最高分。

## 门派选择界面

`SectSelectionController` 在构造门派详情副本时，同时使用当前查看门派 ID 和
当前 `_selected_difficulty` 查询成绩，并只替换该副本用于详情元数据的 `sect`
文本：

- 难度 0：`最高分：xxx`；
- 难度 1：`进阶一：yyy`；
- 难度 2：`进阶二：yyy`；
- 依此类推至难度 9 的 `进阶九：yyy`。

没有记录时显示 0。汉字数字复用门派选择控制器现有的难度数字表。左右箭头
切换并保存难度后，下一次打开门派详情读取新难度的成绩。查看详情期间箭头仍按
现有规则禁用，不增加详情打开时动态切换难度的交互。

难度 0 的现有文案保持完全兼容。普通卡牌详情仍显示卡牌所属门派，只有从门派
目录打开的门派详情替换这一项文本。

## 生命周期与重置

- 普通胜利、失败、奖励和活动轮次中的场景切换不改写最高分；
- 通关在保存前原子写入分难度最高分，然后执行现有通关重置；
- 通关重置保留全部门派、全部难度的最高分；
- `闭关重修` 保留全部最高分；
- `封剑归隐` 使用全新默认存档，清空全部最高分；
- 测试模式的临时卡牌解锁不影响最高分。

难度解锁仍按现有规则在通关难度 `n` 后解锁 `min(n + 1, 9)`，与成绩向下同步
互不替代。

## 组件边界

### `DeckProfileStore`

负责 schema 11 默认值、严格校验、修复、旧成绩迁移、单值成绩读取、最终分
封顶、向下同步以及各种重置的保留语义。最终得分和最高分不能由 UI 重算。

### `SectSelectionController`

负责根据当前已保存的难度和查看中的门派格式化详情文案。它不写入成绩，也不
决定封顶或同步规则。

### `EndingController`

继续只显示结局摘要中的 `score`。它不需要知道难度，也不再对分数进行二次
限制。

## 自动化验证

### 存档与迁移

- 新存档使用 schema 11，并以空的嵌套成绩字典开始；
- schema 10 的旧门派最高分迁移到难度 0、1、2；
- 旧高分在难度 0、1 封顶 500，在难度 2 完整保留；
- 非法门派、难度键、分数类型和负分被拒绝或修复；
- 当前 schema 中难度 0、1 超过 500 无法通过严格校验，修复后为 500；
- 缺失成绩通过单值接口返回 0。

### 通关计分

- 难度 0 和 1 的结局摘要分数及最高分均不超过 500；
- 难度 2 至 9 仍使用未封顶的现有公式；
- 高难度成绩更新当前难度和全部较低难度；
- 低难度上限按目标难度分别应用；
- 不更新高于当前轮次的难度；
- 较低成绩不会覆盖较高成绩；
- 不同门派的成绩互不影响；
- 通关和 `闭关重修` 保留成绩，`封剑归隐` 清空成绩。

### 门派选择集成

- 难度 0 无成绩及有成绩时分别精确显示 `最高分：0` 和对应数字；
- 难度 1 至 9 使用准确的 `进阶n：yyy` 汉字文案；
- 箭头切换难度后再次查看同一门派，显示对应难度成绩；
- 查看不同门派时读取各自成绩；
- 普通预览卡牌详情继续显示原门派名。

## 手动验证与完整回归

实现完成后运行完整规范套件：

```powershell
powershell -ExecutionPolicy Bypass -File tools/run_tests.ps1
```

并在 540×960 竖屏流程中实际检查：

- 难度 0 的门派详情保持现有样式和文案；
- 难度 1、2 及一个更高难度能显示各自成绩；
- 左右切换后重新打开详情不会沿用上一个难度的数字；
- 难度 0、1 的结局分数不超过 500；
- 高难度通关后的低难度详情得到相应提升。

## 非目标

- 不新增具体进阶战斗效果；
- 不修改敌人、牌组、AI、奖励或战斗结算；
- 不在结局画面额外显示难度标签；
- 不改变难度选择、解锁和箭头交互规则；
- 不为未解锁难度预先生成成绩。
