# 四边负一点牌的静态评估设计

日期：2026-09-13

## 目标

修正 AI 对四边均为 `-1` 的特殊牌的系统性低估。当前静态评估直接相加
四边点数，使这种牌只贡献 `-4` 点资源价值；当牌进场后因自身效果离场时，
这项负价值随之消失，搜索因此容易把“尽快用掉它”误判为收益。

本次只修正通用静态评估，不针对任何卡牌 ID，也不改变四边 `-1` 在游戏
规则中的特殊语义。

## 评估规则

计算一张牌的资源价值时：

- 若四条边**全部恰好等于 `-1`**，仅在静态评估中把它们视为
  `[6, 6, 6, 6]`，点数部分贡献由 `-4` 改为 `24`；
- 其它任何点数组合继续按实际四边之和计算；
- 单条或部分负数不触发替代规则，例如 `[-1, 6, 6, 6]` 仍按实际和
  `17` 计算。

替代发生在通用的单牌资源价值函数中，因此自然适用于手牌和场上牌；若
测试专用的牌库价值开关被启用，也沿用同一替代。内力和运行时能力数量的
现有权重保持不变。

## 不改变的内容

- 不修改卡牌实际点数、攻击合法性、点数比较或四边 `-1` 的特殊规则；
- 不修改终局计分，终局仍按真实场面计分；
- 不修改结构排序、PV、History、置换表、贪心回退或平分裁决；
- 不修改状态键、存档、回放、网络/展示数据或卡牌目录；
- 不把四边 `-1` 当作能够以普通六点发动攻击；
- 不添加卡牌 ID 特判或新的生产配置开关。

结构排序继续读取真实点数。这样，本次实验只回答“叶节点评估是否应更重视
特殊牌”，不会同时改变搜索遍历顺序而混入第二个变量。

## 实施位置

修改原生搜索内核 `DuelNativeCompactKernel::evaluate_baseline()` 使用的通用
单牌资源价值计算。检测和替代只需遍历现有四条边，不引入区域扫描、目录
查询或动态分配。

## 验证

### 正确性

增加固定局面测试，至少证明：

1. 其它条件相同时，四边均为 `-1` 与四边均为 `6` 的牌贡献相同的点数
   资源价值；
2. 部分为 `-1` 的普通组合仍按真实点数求和；
3. 生产默认评估使用新规则，游戏规则和终局分数没有变化；
4. 原生搜索仍不依赖命名卡牌 ID。

行为改动完成后运行完整自动化套件。

### 性能

这是搜索热路径改动。实施前保留完全对应的旧源码与 Release 原生构建，
实施后以相同机器、相同局面和相同配置交错运行旧、新版本。记录耗时、节点
数、吞吐率、评分和动作；若出现可重复的性能回退，立即报告，不用后续优化
掩盖。

### 棋力对照

复用敌人目录 Extended 的 28 组配对、每组四局换边赛程，共 112 局：

- 使用进阶 0；不启用任何额外进阶效果，但保留进阶 0 的基础开局规则，
  包括后手的两张相邻八卦方位；
- 双方均使用 `self_turn` 固定深度 2；
- 无时间上限和节点上限；
- 双方使用相同原生规则、PV、History、8 MiB 置换表和完整信息；
- 实验组只启用本次四边 `-1` 评估替代，对照组使用改动前评估；
- 每局完成后立即输出并写入进度记录。

报告总得分率、胜负和、终局分差、先后手/牌组分项、节点数与耗时，并确认
所有决策都完整达到固定深度 2，没有回退、非法行动、缺局或重复赛程。是否
接入生产依据完整报告判断，不预设单一胜率门槛。

## 风险与回退

主要风险是统一的六点代理值仍可能高估或低估不同特殊牌，但它比按实际
`-4` 计价更符合这类牌以强力能力换取普通点数语义的共同设计。若 112 局
结果不理想，只回退这一项评估替代；由于没有修改规则状态和数据格式，回退
不涉及存档迁移。
