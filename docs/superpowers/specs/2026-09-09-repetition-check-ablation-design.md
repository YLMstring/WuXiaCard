# 五次重复终局检查消融设计

## 目的

测量“五次重复”终局检查对原生 AI 搜索速度，尤其是回合收尾耗时的实际影响，判断后续是否值得优化该路径。

## 临时诊断开关（测量后已移除）

测量期间曾新增默认关闭的 `diagnostic_disable_repetition_check`：

- 默认值为 `false`，正式游戏继续执行现有五次重复终局规则。
- 仅性能诊断脚本显式传入时跳开关。
- 开启后，`is_terminal` 跳过 `repetition_hashes` 的五次重复统计。
- 九宫已满、行动上限、双方均无可用行动、额外出牌等待等其他终局规则不变。
- 回合边界仍照常记录棋盘重复签名，使消融只测量“检查”成本，不混入“记录”成本。
- 开关不写入存档，不进入玩家设置，不改变状态键。

## 接线范围

沿用现有 `diagnostic_disable_aura_queries` 的诊断链路：

1. 原生内核保存默认关闭的布尔开关并提供 setter。
2. 原生规则桥接层只在诊断配置显式开启时设置它。
3. 开局性能脚本及 PowerShell 包装脚本增加对应参数。
4. 报告记录该开关是否启用，避免混淆基线与消融结果。

## 验证

使用同一份 Windows `Release + template_debug` 原生库、相同的三个 `quick_unique` 开局和每局 5000 节点，运行：

- Baseline：重复检查开启。
- NoRepetition：仅关闭五次重复检查。

对比总耗时、节点每秒、应用状态耗时、回合收尾耗时，同时核对动作、评分、节点数、事件/攻击等遍历计数。由于搜索树内可能到达重复终局，动作或评分不一致将被明确报告，不能把这种差异误算成纯速度收益。

本次只建立测量开关并产出对比数据，不据此修改正式重复终局规则。

## 测量结果

2026-09-09 使用相同的三个真实 Quick 开局、每局 5000 节点，交替运行三轮 Baseline/NoRepetition，再以相反顺序交替三轮：

- Baseline 总耗时中位数：1.355 秒。
- NoRepetition 总耗时中位数：1.199 秒，快 11.53%。
- 回合收尾中位数：288.60 毫秒降至 235.27 毫秒，快 18.48%。
- 18 个逐局样本的动作、评分、节点、状态应用数、事件发现数、攻击结算数和访问子节点数全部一致。
- 六组成对总耗时变化为 `+7.93%`、`+16.18%`、`+18.32%`、`+12.99%`、`-1.94%`、`+7.70%`；总耗时存在机器波动，但回合收尾的稳定下降证明重复统计本身是有效优化目标。

结论是保留正式五次重复规则、优化统计实现，而不是删除规则。消融完成后，重复检查和光环消融的临时开关均已从原生内核、桥接层和基准脚本中移除。
