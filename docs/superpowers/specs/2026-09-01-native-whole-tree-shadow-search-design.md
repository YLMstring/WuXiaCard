# 原生整树影子搜索设计

日期：2026-09-01

## 目标

在测试专用的 `DuelNativeCompactKernel` 中实现固定完整轮次深度的搜索，验证一次把根状态转换为紧凑表示后，整棵搜索树都能留在 C++ 内完成。测试将其结果与现有 `DuelSearch`/`DuelSimulator` 权威路径对照，但不会改变生产 AI、玩家对局、测试模式或贪心回退的调用路径。

## 边界

- 第一阶段只实现 `baseline` 评分、确定性完整 minimax 和完整轮次深度。
- 不实现迭代加深、截止时间、取消、PVS、置换表、战术延伸或同回合计划复用。
- 一次 GDScript→C++ 根载入；搜索节点之间只复制和修改 `NativeState`。
- 搜索只返回纯数据：是否支持、根动作、评分、节点数、叶节点数、最大动作层数和耗时。
- 任一分支遇到尚未覆盖的规则时，整个影子搜索明确返回不支持，不近似结算。

## 原生组件

1. `NativeAction`：紧凑保存出牌或主动能力动作所需的索引和实例身份。
2. 分支动作枚举：以任意 `NativeState` 为输入，保持与 `DuelSimulator.get_legal_actions()` 相同的合法动作集合。
3. 分支转移：把现有出牌/主动能力结算提炼为对任意源状态生成独立目标状态的内部函数；公开的单步探针继续复用它。
4. 基线评分：逐项复刻 `DuelEvaluator` 的终局、场面差、手牌、牌库、点数、内力、能力数量、机动性、危险度和行动权评分。
5. 固定深度 minimax：深度单位沿用生产规则。根深度 `n` 等于 `2n` 个 `owner_turn_serial` 边界；额外出牌不消耗深度，自动空回合按模拟器实际跨过的边界扣减。

## 确定性

同分根动作按 `DuelAction.canonical_key()` 的字典序选择。搜索内部可以不复制生产排序启发式，因为完整 minimax 的分数不依赖动作顺序；第一阶段不做 alpha-beta 剪枝，从而让影子对照先验证规则、评分和深度语义，不把剪枝正确性混入结果。

## 验证

- 用所有 14 个真实 Quick 开局进行固定完整轮次深度一对照。
- 每个开局比较：支持状态、根合法动作集合、最终评分和规范化根动作。
- 对若干可控小局面跑深度二，覆盖额外出牌、主动能力和自动空回合。
- 报告原生与 Oracle 的节点数和耗时，但第一阶段没有生产性能门槛。
- 原生探针、相关搜索测试和完整 71 套测试全部通过后，才能把这一阶段标记完成。

## 生产门禁

本阶段完成仍不等于可直接替换生产 AI。进入生产前还需要迭代加深/超时/取消、LazyOnly 等价策略、足量全局面/整局影子证据、选中结果一次恢复，以及 Windows Release 与 Android ARM64 打包验证。
