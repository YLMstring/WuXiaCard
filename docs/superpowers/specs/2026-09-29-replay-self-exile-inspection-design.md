# 回放中检视敌方自移除牌

状态：创作者已批准；按本文档实施。

## 问题与目标

正常对局中，敌方手牌在打出前盖住；打出后 `DuelController` 进入 `RESOLVING`，普通轻触检视被禁止。若该牌在同一次动作中自移除，`card_exiled` 呈现后牌视图也会释放，玩家事后没有可点的目标。当前 `YuNvWuFeng` 以及其它使用 `ACTION_EXILE_SELF` 的牌会遇到这一情况。延长移除动画不能解决结算期不能检视的问题。

正常对局保持现有连续播放，不弹窗、不增加出牌记录。只有回放敌方打出的、会在这次动作里自移除的牌时，自动打开已有卡牌检视。玩家按现有方式关闭检视后，回放从暂停处继续。两种回放入口——整局回放与“回放对手回合”——行为相同。

## 触发与时序

一次有效的 `TYPE_PLAY` 动作须同时满足：行动者是敌方；正在整局回放或对手回合回放；这次模拟器返回的事件中有 `type == card_exiled`、`self_removal == true`，且 `instance_id` 等于本次打出的实例。用实例 ID 匹配，不用目录卡名推断，也不因为其它牌被移除而弹窗。每次敌方出牌最多弹一次；同名牌在不同回放动作中分别判断。测试用的快速呈现模式跳过自动弹窗，避免无人操作的现有套件挂起；专门的集成测试使用正常呈现模式验证它。

在模拟器成功返回、敌方出牌视图公开且已完成通常的出场停顿后、这次动作的事件动画开始前，以该牌当前公开视图数据的深拷贝打开现有 `CardInspector`。因此先读文字，再看点数变化、自移除及后续效果。即便模拟器返回的最终 `DuelState` 已经没有这张牌，检视也只依赖这份公开快照。对于打在已占用格的特殊出牌，视图可能还在等待 `card_placed` 事件，此时先检视已公开的出牌视图，关闭后再完成落位；无需为此另开一条事件顺序。

该入口是回放专用的呈现方法，不能放宽普通 `_on_card_inspection_requested` 对 `RESOLVING` 的拒绝条件。弹窗期间保持原动作的结算协程等待，不提交下一动作，不改变 `DuelState`、`DuelAction` 或事件列表。关闭检视后恢复棋盘与比分，再继续原事件顺序，包括 `card_exiled` 淡出和自移除后的额外出牌。现有整局回放间隔计时已经在检视打开时暂停；对手回合回放的下一动作也要等当前动作与检视完成。

若退出场景或取消回放，等待中的呈现不得在失效节点上继续；按现有回放代数/状态检查终止。正常对局、玩家打出的自移除牌、普通敌方出牌、敌方发动能力、其它卡牌被移除，均不自动打开检视。敌方仍盖着的手牌不进入快照，不增加信息泄露。

## 实现边界

只在 `scripts/duel_controller.gd` 的成功出牌呈现路径判断并展示，不改原生模拟器、搜索、卡牌目录或存档。不建立最近出牌记录、跨回合 UI 状态或新的通用事件框架。检视继续使用 `scripts/card_inspector.gd` 的既有布局、中文换行和关闭手势。若需要测试观察点，只暴露呈现侧调试状态，不把节点或弹窗状态写入 `DuelState`。

## 验证

- 基线及改动后运行 `tools/run_tests.ps1`。现有快速模式的回放与集成测试仍应完成，不等待玩家点击。
- 集成测试构造会自移除的敌方出牌：正常对局不弹窗；整局回放和对手回合回放各弹一次，检视快照是实际已公开的出牌实例；关闭后继续播放移除及其后续事件。另一张牌被移除、敌方发动能力和玩家自移除都不触发。
- 检查重复同名出牌各按动作触发一次、回放退出/失败恢复时不会留下检视遮罩或挂起的协程。静音、540×960 逻辑竖屏下走一次回放入口，确认阅读与关闭操作可用，并读取运行时错误。
