# 通关后清除卡牌解锁设计

## 目标

最终胜利关闭一轮游戏时，卡牌相关进度与“闭关重修”保持一致：恢复初始卡牌解锁、主卡组和牌库，同时保留永久门派、成绩与熟练度进度。

## 最终胜利顺序

`record_completed_duel_and_save()` 在确认达到通关胜场数后仍按当前顺序完成：

1. 记录本场有效对局和击败的最终敌人。
2. 解锁最终敌人声明的门派。
3. 提交本次胜利获得的卡牌熟练度。
4. 从重置前的完整档案生成结局摘要。
5. 更新该门派的最高分。
6. 使用与“闭关重修”相同的规则构造关闭后的档案。
7. 验证并原子保存一次。

结局摘要因此仍包含完整的门派、击败敌人、有效对局数和得分。重置只影响结局之后持久化的下一轮准备状态。

## 共用重置规则

从现有 `reset_run_and_save()` 中抽取一个不保存文件的纯 helper。它以待保留进度已经写入的有效档案为输入，从 `create_default_profile()` 建立候选档案，再复制：

- `unlocked_sect_ids`：保留，包括最终敌人本次新解锁的门派；
- `best_scores_by_sect`：保留，包括刚记录的本次通关成绩；
- `mastered_card_ids`：保留，包括最终胜利刚提交的熟练度。

其余字段采用初始档案值。因此：

- `unlocked_card_ids` 只含初始的太祖长拳与一级吐纳术；
- `main_deck` 恢复初始两张牌；
- `library_slots` 恢复初始空牌库；
- 当前门派、等级、敌人、记忆、待选奖励、保证奖励展示记录、有效对局数和击败敌人历史全部清空；
- `run_active` 为 `false`。

`reset_run_and_save()` 与最终胜利关闭流程都调用该 helper。公开重置函数负责保存；最终胜利事务继续在记录摘要和最高分后只保存一次，保存失败时返回原档案，不产生半完成状态。

## Testing Mode

测试模式的“全卡牌临时解锁”仍由运行时流程在加载档案后创建，不写入永久存档。通关后保存的底层档案仍只保留初始卡牌；下一次测试模式进入时可以再次临时获得全卡牌。

## 测试

- 最终胜利后卡牌解锁严格等于初始卡牌集合。
- 最终胜利后主卡组和牌库严格等于初始档案。
- 先前及最终敌人新解锁的门派全部保留。
- 本次最高分与全部既有最高分保留。
- 既有熟练度和最终胜利刚提交的熟练度保留。
- 结局摘要在重置前生成，仍包含完整通关历史。
- 闭关重修现有行为保持不变。
- 保存失败继续回滚到输入档案。
