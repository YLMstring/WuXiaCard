# 新手流程完成计数事件设计

## 目标

统计有多少匿名玩家完成华山派进阶零的新手流程并进入正式流程，从而与最终通关
玩家数对比，估算新手流程结束后的流失。该事件只用于计数，不包含卡组、敌人、
胜负、分数或行动记录。

## 触发边界

唯一触发时点是玩家战胜第二个新手敌人“江湖武师”，进度存档成功地从
`BEGINNER_OPENING_WUSHI` 切换为 `BEGINNER_OPENING_NONE`，下一战变为
“少镖头·林平之”之后。不等待玩家挑战或战胜林平之。

只有正常导出的遥测启用环境生成事件；编辑器测试模式、自动化测试、AI 基准和
未启用遥测的构建继续禁止真实上传。事件生成失败不得影响进度保存、奖励选择或
界面切换。

## 事件与去重

事件类型固定为 `beginner_flow_completed`，正文只包含：

- 事件格式版本；
- 稳定的 `event_id`；
- 现有随机匿名玩家 ID；
- 事件类型；
- 游戏版本和平台；
- 客户端发生时间。

`event_id` 由匿名玩家 ID 与事件类型确定性生成。同一个匿名玩家即使重新开始并
再次完成新手流程，也对应同一个服务端文档 ID。客户端同时持久化已生成的事件
类型，避免重复排队；服务端唯一键作为第二层幂等保护。卸载或清除应用数据会像
现有通关报告一样生成新的匿名身份。

## 本地生命周期

`BalanceTelemetryStore` 的本地格式升级一版，新增：

- `pending_events`：等待上传的事件；
- `recorded_event_types`：已经生成过的安装级事件类型。

必须显式迁移旧格式：保留原匿名玩家 ID、活动轮次、待上传通关报告和诊断，仅为
旧状态补充两个空数组。不得把旧遥测文件当作损坏数据重建，否则会丢失匿名身份
和离线报告。

事件先与已生成标记在同一次原子保存中落盘，再异步上传。断网、超时、限流和
服务器错误保留事件，之后进入主菜单时沿用现有离线重试。服务端明确保存或返回
重复成功后，从 `pending_events` 删除事件，但保留 `recorded_event_types`。永久
格式错误保留事件并记录诊断，不在同一次启动中热重试。

## 上传与服务端存储

同一 CloudBase 云函数新增：

```text
POST /v1/events
```

客户端从现有 `/v1/reports` 地址派生同源 `/v1/events` 地址，不新增第二套云端
配置。上传器继续串行发送：一项完成后再处理下一项，通关报告与计数事件共享忙碌
状态、超时和响应分类，但分别调用对应的本地确认或错误记录接口。

服务端严格白名单校验事件字段、正文大小、事件类型、平台、ID 和时间；事件写入
独立集合 `player_events`。重复 `_id` 返回与通关报告一致的幂等成功语义。
`run_reports` 的既有结构、校验和 CSV 不变。

## 管理导出与统计口径

现有管理导出增加 `dataset=events`：

```text
GET /v1/admin/export?dataset=events&format=csv
GET /v1/admin/export?dataset=events&format=json
```

不传 `dataset` 时仍导出现有通关报告，保持当前脚本和调用兼容。下载脚本增加
`-Dataset Events` 选项。事件 CSV 每个匿名玩家一行，JSON 返回事件数组，并继续
支持日期筛选和管理员 Bearer token。

由于事件按匿名玩家唯一，`player_events` 文档数就是完成新手流程的安装数。统计
未通关人数时，应在相同版本/发布时间范围内，用事件匿名 ID 集合减去通关报告中
出现的匿名 ID 集合；旧版本、其它门派或其它难度的通关报告不能直接混入这一
新手漏斗分母。

## 验证

1. 只有战胜江湖武师并成功进入林平之流程时生成事件；令狐冲胜利、两场失败、
   林平之胜利及其它门派/难度均不生成。
2. 同一匿名玩家重复完成新手流程仍只有一个已生成标记和一个服务端文档。
3. 旧遥测状态迁移后保留匿名 ID、活动轮次和待上传报告。
4. 事件断网后留在队列，成功或重复响应后移除，永久错误保留并停止热重试。
5. 测试模式和未启用构建不发送网络请求。
6. 服务端拒绝未知事件类型、非法 ID、平台、时间、额外字段和超大正文。
7. 管理端可分别导出通关报告和事件，原有无 `dataset` 下载行为不变。
8. 在 CloudBase 创建 `player_events`、部署函数后，用合成事件验证上传、去重、
   CSV/JSON 下载，再删除合成数据。
