# 金针渡劫与万花剑法能力设计

## 范围

实现 `JinZhenDuJie2`、`JinZhenDuJie3`、`JinZhenDuJie4`、
`WanHuaJian1`、`WanHuaJian2`、`WanHuaJian3`，并把尚未登记的五个高阶
ID 加入 `ALL_CARD_IDS`。所有效果必须由通用能力声明驱动，模拟器、AI、回放与
实际对局共享同一套结算，不加入按卡牌 ID 分支的规则代码。

`锁定`在本设计中表示该能力 `retained_on_flip = true`。所有触发能力仍然是强制
结算的；没有写 `锁定` 的能力沿用默认值，翻面后失去。

## 通用词汇

新增以下名称固定的可复用词汇：

- `TRIGGER_BEFORE_DUEL_END`：回合结束效果结算完毕、九格已满、对局正式终止
  之前触发。
- `CONDITION_OWNER_DID_NOT_WIN`：能力来源的当前拥有者不在本次结束尝试的胜者
  列表中。
- `CONDITION_ATTACKED_CARD_IS_SELF`：本次 `CARD_BE_ATTACKED` 的被攻击牌就是
  能力来源。
- `CONDITION_SELECTED_CARD_ORIGINAL_OWNER_IS_SELF`：被选牌的 `original_owner`
  等于能力来源的当前拥有者。
- `ACTION_RETURN_SELF_TO_ABILITY_SOURCE_HAND`：把当前被选牌从场上移走，并在
  能力来源拥有者的手牌中生成同 ID 的全新目录实例；手牌已满时改为放逐场上
  实例。
- `ACTION_SUMMON_FRESH_COPY_IN_FIRST_ADJACENT_EMPTY`：在能力来源相邻的首个
  空格生成同 ID 全新实例，并走完整召唤与攻击流程。
- `ACTION_EXILE_SELF`：若能力来源仍在场上，放逐其当前实例。

这些动作只返回既有的 `APPLIED` 或 `NO_EFFECT`，不为这些卡牌引入
`INVALID_CONTEXT` 或其他特殊失败语义。

## 对局结束尝试

模拟器的回合结束流程调整为：

1. 结算 `TRIGGER_END_OWNER_TURN`。
2. 增加回合计数与状态版本。
3. 若棋盘未满，继续既有的额外回合、换手及回合开始流程。
4. 若棋盘已满，用此刻的控制权数量创建一次结束尝试上下文：
   - 玩家多于对手：胜者列表只含玩家。
   - 对手多于玩家：胜者列表只含对手。
   - 平局：胜者列表为空，双方都视为“没有获胜”。
5. 一次性发现所有场上的 `TRIGGER_BEFORE_DUEL_END` 规则，然后依现有稳定顺序
   逐一结算。第一张万花剑法被移除、棋盘不再满，不会取消本次已经发现的其他
   规则；所有条件都使用同一次结束尝试的胜者快照。
6. 全部规则结算后再次检查棋盘：
   - 仍然满：对局成为终局，控制器用最终棋盘显示结果。
   - 出现空格：本次不结束，继续处理原本应当生效的额外回合或换手，然后触发
     正确拥有者的回合开始事件。

若之后棋盘再次填满，则创建新的结束尝试和新的胜者快照。手牌、牌库与已移除区
中的万花剑法不参与 `TRIGGER_BEFORE_DUEL_END`。

## 金针渡劫

### 通用返回能力

`JINZHEN_RETURN` 在自身 `TRIGGER_CARD_AFTER_SUMMONED` 时执行：

1. 按既定棋盘顺序（顶行从左到右，再由上至下）选择首个同时满足以下条件的
   场上实例：
   - 当前是能力来源的敌方；
   - `original_owner` 是能力来源的当前拥有者。
2. 选择以精确实例 ID 锁定。实例在棋盘格之间移动不会使动作跳过；结算时重新
   定位该实例，并在其新格执行。
3. 仅当某项声明条件不再满足时跳过，例如该牌已经变回友方。若实例已离开棋盘，
   动作没有有效场上目标并返回 `NO_EFFECT`。
4. 手牌少于五张时，旧场上实例消失，不进入放逐区；在能力来源当前拥有者的手牌
   末尾生成同 `card_id` 的全新目录实例。新实例重置点数、气、能力与
   `original_owner`；其 `original_owner` 明确设为能力来源的当前拥有者，并取得
   不冲突的新实例 ID。
5. 手牌已有五张时，不生成手牌实例，改用正常放逐流程放逐旧场上实例。

声明组合：

- `JinZhenDuJie2`：`JINZHEN_RETURN`。
- `JinZhenDuJie3`：`JINZHEN_RETURN` + 既有 `HENGSHAN_COUNTERATTACK`。
- `JinZhenDuJie4`：`JINZHEN_RETURN` + 既有 `HENGSHAN_COUNTERATTACK`。

后两者的反击效果不是锁定能力，翻面后失去；触发后按既有规则先移除自身，再在
整次敌方攻击及其翻面连锁完全结束后发起一次标准攻击。

## 万花剑法

### 对局结束能力

`WANHUA_ENDING` 是锁定能力：

- 事件：`TRIGGER_BEFORE_DUEL_END`。
- 条件：`CONDITION_OWNER_DID_NOT_WIN`，以该实例此刻的当前拥有者判断。
- 动作：`ACTION_EXILE_SELF`。

它只在该实例仍在棋盘时存在和触发。翻面不会改变其持续性；它不会从手牌、牌库
或其他区域触发，也不会修改主卡组、解锁数据或局外进度。

### 被攻击时生成复制

`WANHUA_COPY` 在 `CARD_BE_ATTACKED` 且被攻击牌是自身时执行：

1. 结算时从来源当前所在格的正交相邻格中，选择棋盘索引最小的空格。
2. 没有相邻空格时返回 `NO_EFFECT`。
3. 在目标格生成与来源完全相同 `card_id` 的全新目录实例。来源当前拥有者同时
   成为新实例的控制者与 `original_owner`；新实例取得唯一实例 ID。
4. 该生成不消耗手牌、行动或回合，但视为完整召唤：先发出
   `TRIGGER_CARD_SUMMONED`，若实例仍在场则发出 `TRIGGER_CARD_AFTER_SUMMONED`，
   最后在仍属于生成者时发起标准四方向攻击。
5. 复制的召唤、反应与标准攻击在原本的 `CARD_BE_ATTACKED` 继续之前完整结算。
   之后原攻击沿用既有的精确攻击者、精确目标与攻击范围重检；复制引发的连锁可能
   令原攻击失效。
6. 复制若在 `CARD_SUMMONED` 期间离场，不发出 after-summoned 且不攻击。若在
   召唤期间翻面，after-summoned 使用新拥有者；只有仍属于生成者时才执行标准攻击。

声明组合：

- `WanHuaJian1`：只有锁定的 `WANHUA_ENDING`。
- `WanHuaJian2`：锁定的 `WANHUA_COPY` + 锁定的 `WANHUA_ENDING`。
- `WanHuaJian3`：非锁定的 `WANHUA_COPY` + 锁定的 `WANHUA_ENDING`。

因此二阶万花剑法翻面后仍能生成复制；三阶翻面后失去生成复制能力，但仍保留对局
结束前自我放逐的能力。

## 表现与回放

- 所有被动能力沿用短促能力脉冲；连续同源脉冲仍服从现有抑制规则。
- 成功返回时，旧场上视图先以短促透明度渐隐完整消失；渐隐结束后，才用现有
  手牌加入表现生成新视图。两段表现不重叠，模拟器状态仍在单次动作中原子更新。
- 满手时沿用正常放逐表现。
- `ACTION_EXILE_SELF` 造成的自身移除也只播放同一短促渐隐，不播放墨痕放逐
  动画或外力移除反馈；只有被另一张牌移除时才沿用正常放逐表现。
- 万花复制在对应格生成可见卡牌，随后依事件顺序播放召唤反应、攻击线与翻面。
- 对局结束前的多个万花实例按事件顺序逐一脉冲并放逐；全部结束后才显示结果或
  开始下一回合。
- 新事件必须写入既有转移事件流，使回放重建相同棋盘与手牌状态；敌方隐藏信息
  继续遵守当前回放规则。

## 验证范围

新增聚焦测试，至少覆盖：

- 六张卡牌的 ID、能力数量、锁定差异及目录完整校验。
- 金针按行优先顺序选择首个目标。
- 目标在棋盘内移动后仍被追踪，条件改变时跳过，离场时 `NO_EFFECT`。
- 返回生成全新实例并重置目录数据；五张手牌时改为放逐。
- 返回表现严格先完成场上渐隐，再出现手牌新实例。
- 金针三、四阶复用一次性完整攻击后反击。
- 万花选择最低索引相邻空格，复制 ID 唯一，当前拥有者成为 `original_owner`。
- 万花复制完整发出召唤事件并攻击；无空格、召唤中离场、召唤中翻面等边界。
- 万花二阶复制能力翻面保留，三阶复制能力翻面丢失，结束能力始终保留。
- 平局结束尝试会移除双方符合条件的万花实例。
- 移除后棋盘出现空格会继续正确的下一回合或额外回合；没有移除时正常结束。
- 搜索模拟、控制器表现与回放不回归。

## 非目标

- 不新增专属视效或音效。
- 不改变五张手牌上限。
- 不改变平局在最终稳定终局时仍算玩家失败的既有规则。
- 不让万花的局内放逐影响主卡组、解锁、奖励、精通或成就数据。
- 不实现通用空格选择器语言；本次使用受约束的“首个相邻空格”通用召唤动作。
