# 奖励选择界面门派池展示设计

日期：2026-09-14

## 目标

奖励选择界面不再预告下一名敌人，而是直接展示本轮随机门派池，让玩家在
选择奖励时能够查看本轮可能出现的门派及其历史最高分。

本次只调整奖励选择界面的展示与检查交互，不修改门派池生成、奖励候选、
奖励领取、敌人推进或存档格式。

## 界面内容

- 下方常驻提示固定为“选择一张奖励牌，长按拖动至下方”。
- 顶栏左侧印章文字由“敌”改为“友”。
- 顶栏名称由下一场敌人姓名改为“随机门派池”。
- 原上方敌人手牌的五个固定槽位改为展示本轮随机门派池。
- 读取存档中的 `run_sect_pool_ids`，严格按其现有顺序展示五张门派牌。
- 每张门派牌直接使用 `SectCatalog` 中对应门派的定义，固定以敌方显示方
  渲染，因此卡面为红色；全部正面朝上，不再受测试模式或敌人记忆影响。
- 上方槽位沿用现有不可拖动行为，不新增另一套拖动开关或拖动状态。

若有效存档中的门派池不足五项，已有槽位保持存在，缺失项显示为不可交互
的红色牌背；正常有效的新一轮存档仍应始终提供五项。

## 检查交互

轻触任意有效门派牌打开现有卡牌检查卷轴。检查数据以 `SectCatalog` 定义
为基础，并按本轮当前生效进阶写入最高分字段：

- 进阶零：显示“最高分：xxx”；
- 进阶一至九：显示“进阶n：yyy”，其中 `n` 使用现有汉字数字，`yyy`
  是该门派在当前进阶的历史最高分。

最高分读取复用 `DeckProfileStore.get_best_score()`。检查器打开期间，中央奖励
牌库隐藏且不可交互；轻触返回后恢复奖励牌库与默认提示。上方门派牌无需为
检查而隐藏，行为与当前奖励界面检查其它卡牌保持一致。

## 保持不变

- 中央三张奖励牌的随机颜色、气珠、轻触检查和长按拖动领取不变。
- 下方玩家五张卡组不变。
- 奖励只能拖到下方玩家卡组区域领取。
- `upcoming_enemy_name`、`upcoming_enemy_card_ids` 和敌人记忆不再参与该界面
  的可见上方内容；主流程其它场景仍可继续保留这些数据。
- 门派池与奖励候选的过滤规则不变。

## 验证

扩展奖励选择集成测试，至少覆盖：

1. 顶栏显示“友”和“随机门派池”；
2. 下方提示使用新的固定文案；
3. 五张上方门派牌按 `run_sect_pool_ids` 顺序出现，均为红色明牌；
4. 上方门派牌不能触发奖励拖动或领取；
5. 轻触门派牌能打开检查器，进阶零与非零进阶分别显示正确最高分文本；
6. 中央奖励牌拖动领取流程保持通过。

完成后运行完整自动化套件，并在静音竖屏运行中检查顶栏、五张门派牌、卷轴
和下方提示没有遮挡或溢出。
