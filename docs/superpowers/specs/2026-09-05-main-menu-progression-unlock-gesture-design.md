# 主菜单全门派与全进阶解锁手势设计

## 目标

在主菜单加入一个不占用新按钮的隐藏解锁手势。玩家从“闭关重修”开始，
严格交替点击“闭关重修”和“封剑归隐”各五次后，永久解锁全部门派与
难度 0 至 9。

## 固定输入序列

唯一合法序列为：

```text
闭关 → 归隐 → 闭关 → 归隐 → 闭关 → 归隐 → 闭关 → 归隐 → 闭关 → 归隐
```

- 序列必须从“闭关重修”开始，共十次点击。
- 任一步点击错误，隐藏序列立即清零；本次错误点击可作为一条新序列的
  第一步，但只有“闭关重修”能开始新序列。
- 点击“踏入江湖”、离开主菜单或重新创建主菜单实例会清零。
- 不设置额外计时限制；序列只存在于当前主菜单实例的内存中。
- 正确交替时，两个原有破坏性操作的连续确认计数会照常互相取消，因此
  不会意外触发闭关或归隐。

## 架构与数据流

`MainMenuController` 只识别序列并发出一个新的无参数信号。它不读取或
修改存档。`MainFlowController` 接收信号，加载当前档案，并调用
`DeckProfileStore` 的专用原子保存接口。

存档接口基于传入档案的深复制生成候选值：

- `unlocked_sect_ids` 写为 `SectCatalog.get_all_sect_ids()` 的完整稳定顺序；
- `max_unlocked_difficulty` 写为 9；
- 保留 `last_selected_difficulty`；
- 保留当前闯关、`run_difficulty`、卡牌解锁、主卡组、牌库、奖励、最高分、
  精通及其它所有字段；
- 不解锁全部卡牌；
- 通过现有档案校验后原子保存。

保存成功时，当前主菜单显示“已解锁全部门派与进阶”。保存失败时显示
“保存失败，请重试”。无论成功或失败，序列计数都在触发时清零，不会因
一次额外点击重复保存。

以后真正完成“封剑归隐”的十次连续确认时，仍按既有规则清除全部全局
进度，包括本功能解锁的门派与进阶。

## 测试

- 主菜单单元测试覆盖正确十步序列、错误起点、顺序错误、踏入江湖清零，
  并确认交替序列不会发出原有两个重置信号。
- 存档测试覆盖完整门派顺序、最高难度 9、其它档案字段不变以及保存失败
  不修改磁盘档案。
- 主流程集成测试覆盖成功提示、持久化结果和失败提示。
- 实施后运行完整测试套件。
