# 批量加点区域条件设计

## 目标

`CONDITION_POWER_INCREASE_BATCH_INCLUDES_ALLY` 增加必填的 `zone` 参数，使监听者只在指定区域中的友方牌实际获得正向点数变化时通过条件。

目录文案中的“友方”或“敌方”若没有额外说明，默认指场上的牌；若能力涉及手牌、弃牌区或移除区，文案和原语声明都必须明确写出区域。

## 声明

阴阳掌力4获得的批量加点反应声明为：

```gdscript
{
	"type": CONDITION_POWER_INCREASE_BATCH_INCLUDES_ALLY,
	"zone": CARD_ZONE_BOARD,
}
```

`zone` 支持现有四个卡牌区域：`board`、`hand`、`discard`、`removed`。缺少参数或使用未知区域均视为非法目录声明，不提供隐式通配行为。

## 结算

- 每次成功的正向 `powers_changed` 按“变化发生时的区域 × 当时所属方”写入批次上下文。
- 条件以能力来源结算时的当前所属方为“我”，再检查指定区域中是否包含该方的成功加点。
- 同一批次中多张符合条件的牌仍只派发一次 `power_increase_batch_finished`，每个监听者也仍只结算一次。
- 负向变化、无效变化以及四边 `-1` 的不可变牌不进入成功加点记录。
- 批次上下文使用紧凑位掩码，不进入对局状态、存档、回放、状态键或置换表键。

## 阴阳掌力4

只有场上友方点数增加才触发其额外攻击。友方手牌、弃牌区或移除区的点数增加均不触发；若同一批次同时包含手牌和场上的友方加点，只触发一次。

## 验证

- 目录验证拒绝缺少 `zone` 或使用未知 `zone` 的该条件。
- 目录测试核对阴阳掌力4显式声明 `CARD_ZONE_BOARD`。
- 模拟器测试覆盖场上友方触发、仅手牌友方不触发、混合区域只触发一次、仅敌方不触发。
- 扫描其它含“友方/敌方”的目录文案，核对选择器区域与上述默认语义是否一致。
