# 手牌出牌危险区域设计

日期：2026-09-10

## 目标

在玩家拖动一张手牌准备出牌时，为当前合法出牌格增加纯表现层的危险提示。普通合法格沿用现有蓝光；危险合法格改为同等强度的红光。危险提示不改变合法行动、规则结算、AI 判断、回放或存档。

## 显示规则

- 只有拖动手牌时显示危险区域。拖动场上牌选择主动能力目标时不显示。
- 同一个格子不会叠加蓝光和红光。危险状态优先：
  - 合法且安全：蓝光；
  - 合法且危险：红光；
  - 非法：普通底色，即使它位于危险来源的覆盖范围内也不发光。
- 红光采用已确认的 A 方案：完全沿用现有蓝色合法格的透明度、边框粗细和发光强度，只把色相替换为与当前水墨界面协调的危险红。
- 指针悬停危险格时仍保持红色，只提高到与现有蓝色 hover 对应的填色、边框和光晕强度。
- 松手、取消拖动、开始结算或清理拖动上下文时，红蓝高亮一并清除。

## 危险来源

只检查拖牌所属方的敌方场上牌。友方能力永远不会令格子标红。

危险来源按当前运行时能力的通用语义识别，不检查具体卡牌 ID 或名称。当前有三类：

1. `CARD_AFTER_SUMMONED` 后置迎击：苍松迎客、七星落长空使用的“对手招式进场后，若在我的攻击范围内，我攻击它”。
2. `CARD_SUMMONED` 即时迎击：金刚伏魔圈向场上牌分发的“对手招式进场时，若在我的攻击范围内，我攻击它”。
3. 太极剑共通改向：具有 `MODIFIER_ADJACENT_ENEMY_SUMMON_ATTACKS_ALLIES` 的敌方牌令其正交相邻空格成为危险格。

前两类通过已编译的触发、条件和动作 opcode 识别。一个运行时能力只有同时包含下列语义才算迎击来源：

- 触发事件是 `CARD_SUMMONED` 或 `CARD_AFTER_SUMMONED`；
- 条件包含 `CONDITION_TRIGGER_CARD_IS_ENEMY`；
- 条件包含 `CONDITION_TRIGGER_CARD_IN_RANGE`；
- 动作包含 `ACTION_ATTACK_TRIGGER_CARD`。

因此金刚伏魔圈动态授予的能力会自动被识别；失去相应运行时能力的牌不再产生危险区域。查询只考虑能力当前存在且在棋盘区域有效，不扫描手牌、牌库、弃牌区或移除区。

## 范围语义

后置和即时迎击来源按来源牌当前的几何攻击范围标记空格：

- 普通攻击范围为正交相邻格；
- 当前运行时远程、无限距离或非正交攻击范围 modifier 继续生效；
- 距离二攻击继续按照当前中间格及 modifier 对“隔空、隔友方、隔敌方”的许可判断；
- 目标格按一张即将由拖牌所属方进场的敌方牌处理。

危险提示只表达“看上去危险”，不预测真正结算。它不检查：

- 攻防点数是否足以造成攻击；
- 来源牌是否因 `CANNOT_ATTACK`、其它友方要求、内力、门控或后续连锁而无法实际迎击；
- 进场牌是否会先移动、翻面、离场、出牌方改变或令迎击能力失效；
- 太极剑改向后是否真的存在可攻击目标。

太极剑类不使用来源牌攻击范围，只标记来源牌当前正交相邻的空格。

## 架构与数据流

`DuelNativeCompactKernel` 新增独立、只读的批量查询，例如 `get_hand_play_danger_flags(owner_id)`，返回与棋盘九格一一对应的布尔数组。查询遍历敌方棋盘牌的当前运行时能力，并复用现有编译后的 trigger、condition、action 和 modifier opcode 语义。它可使用以下实现辅助函数：

- 判断一个编译能力是否具有上述两种迎击结构；
- 判断某个棋盘来源是否覆盖一个假设中的敌方空格；
- 汇总所有敌方来源和太极剑相邻格，生成九格危险位图。

`DuelNativeRules` 和 `DuelSimulator` 仅提供类型化转发。`DuelController` 不解析能力声明，也不认识任何卡牌名称。

控制器的拖动流程维护独立的 `_drag_danger_targets`：

1. `_get_drag_targets()` 继续取得该精确手牌实例的模拟器合法出牌格；
2. 仅当拖动来源是手牌时调用危险位图查询；
3. 将危险位图与合法目标取交集；
4. `_highlight_legal_cells()` 按危险优先选择 `danger`、`legal` 或 `normal`；
5. 悬停时按是否危险选择 `danger_hover` 或现有 `hover`；
6. `_clear_drag_context()` 和现有高亮清理同时清空危险目标。

查询失败、状态无效或返回长度异常时，控制器把危险集合视为空。合法格仍显示蓝光，纯表现信息绝不阻止玩家操作。

## 性能边界

危险位图只在一次手牌拖动开始时对当前根局面查询一次。它不会被以下路径调用：

- 原生合法行动生成；
- AI 搜索节点展开；
- 规则事件发现与结算；
- 状态键、置换表和局面评估；
- 每帧 `_process`。

本功能不修改通用攻击合法性或合法行动热路径。若实现中发现必须触及这些热路径，应暂停实施并先报告可能的性能影响。

## 验证

### 原生语义测试

- `CARD_AFTER_SUMMONED` 迎击标记来源攻击范围；
- `CARD_SUMMONED` 动态获授迎击标记来源攻击范围；
- 太极剑 modifier 标记正交相邻格；
- 友方来源不标记；
- 对应能力失去后不标记；
- 距离二与当前中间格许可匹配现有范围 modifier；
- 即使来源点数不足，几何范围仍标记为危险。

### 控制器集成测试

- 安全合法格使用蓝色样式；
- 危险合法格使用红色样式；
- 危险但非法的格子保持普通样式；
- 危险格 hover 保持红色；
- 拖动结束或取消后恢复普通样式；
- 场上主动能力拖动不显示危险区域。

### 完整验证

1. 重新编译 Windows `template_debug` 原生库；
2. 运行新增定向测试；
3. 运行 `powershell -ExecutionPolicy Bypass -File tools/run_tests.ps1`；
4. 在 540×960 纵向运行态、主音频总线静音的条件下，分别放置三类危险来源并检查红蓝层级、hover 和清理；
5. 检查运行控制台和调试器没有新增错误或警告。
