# 非抽牌入手牌公开规则设计

日期：2026-08-26

## 目标

除正常抽牌外，任何由卡牌效果将牌加入手牌的行为，都令新入手的牌对另一方永久可见。

该规则对双方完全对称：玩家通过效果获得的牌对敌方公开；敌方通过效果获得的牌对玩家公开。

## 规则边界

以下行为属于公开入手：

- `ACTION_ADD_CARD_TO_HAND` 创建的新牌、全新复制和完整运行时复制；
- `ACTION_RETURN_CARD_TO_HAND` 将场上牌作为新实例返回手牌；
- `ACTION_RETURN_CARD_TO_HAND` 将弃牌区中的同一实例返回手牌。

以下行为不因本规则自动公开：

- `ACTION_DRAW_CARDS` 产生的普通 `card_drawn`；
- 开局时已经位于双方主手牌中的牌。

正常抽牌仍可被既有揭示能力公开，例如已启用的未来抽牌揭示。该行为维持现有规则，不视为本规则的例外实现。

若手牌已满，效果未能把牌加入手牌，则不产生新的公开状态或揭示事件。已经对另一方公开的牌再次进入手牌时，不重复发出揭示事件。

## 数据与事件

公开状态继续使用牌实例已有的 `revealed_to_owner_ids`，不增加并行的 `public` 或展示专用字段。

每次非抽牌入手成功后：

1. 确定接收手牌的所属方及其对手；
2. 调用通用揭示逻辑，将对手加入该牌实例的 `revealed_to_owner_ids`；
3. 先发出原有的 `card_added_to_hand` 或 `card_returned_to_hand`；
4. 若本次确实新增了公开对象，紧接着发出 `card_revealed`。

入手事件中的 `card` 快照必须已经包含更新后的公开状态，使控制器在首次创建手牌视图时直接显示正面。随后的 `card_revealed` 保持既有事件语义，并支持一致的事件记录和展示追踪。

`card_drawn` 的数据与事件顺序不变。只有既有的未来抽牌揭示机制才会在其后发出 `card_revealed`。

## 架构位置

规则实现在 `DuelSimulator` 使用的通用能力执行路径中，不在 `DuelController` 根据卡牌 ID 或事件类型伪造可见性。

`duel_ability_executor.gd` 提供一个小型通用辅助逻辑，用于给成功入手的牌添加对手公开状态，并按需生成 `card_revealed`。`ACTION_ADD_CARD_TO_HAND` 与 `ACTION_RETURN_CARD_TO_HAND` 的两个成功分支共同复用该逻辑。

`DuelController` 继续只根据逻辑牌的 `revealed_to_owner_ids` 决定是否隐藏手牌。这样正常对局、测试模式、回放和视图重建共享同一真实状态。

## 测试

模拟器测试覆盖：

- 创建或复制牌入手后对手在 `revealed_to_owner_ids` 中；
- 从弃牌区返回的同一实例对手可见；
- 从场上返回的新实例对手可见；
- 入手事件后紧跟一次 `card_revealed`；
- 已公开实例不会重复发出 `card_revealed`；
- 满手失败不改变公开状态；
- 普通抽牌仍只对持有者可见，既有未来抽牌揭示规则继续有效。

集成测试覆盖敌方通过效果获得牌时，玩家立即看到正面，并验证重新构建视图后仍保持正面。玩家获得牌的状态使用对称模拟器断言覆盖。

完成后运行相关能力、揭示、控制器和回放套件，并按仓库规则运行一次完整套件。
