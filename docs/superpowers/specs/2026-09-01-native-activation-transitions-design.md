# 原生主动能力事务设计

日期：2026-09-01

## 目标

在测试专用的 `DuelNativeCompactKernel` 中一次覆盖当前牌库的全部主动能力：

- 原生编译主动能力的目标规则、费用和动作；
- 原生枚举合法主动行动；
- 原生验证并执行指定主动行动；
- 完整复用已经迁移的动作、攻击、进场、移动、抽牌、弃牌、能力变化和回合边界；
- 对所有进入覆盖范围的行动，与权威 `DuelSimulator` 比较完整状态和事件。

本阶段不把原生内核接入生产搜索。生产、人类操作、测试模式和贪心回退仍由
`DuelSimulator` 统一裁决。

## 已确认范围

一次覆盖当前目录中的全部主动能力，而不是只实现一张牌或一种目标：

- 相邻空格；
- 相邻友方；
- 相邻敌方；
- 其它友方；
- 友方手牌；
- 敌方手牌；
- 任意空格；
- 任意敌方。

当前主动能力费用均由一个或多个正整数 `spend_ki` 声明组成。实现按通用累计费用处理，
不写死“一次只花一点”。同一张牌可以先天拥有多个主动能力，并按当前有效主动能力条目
的目录顺序编号。动态获得主动能力仍沿用既有规则：替换全部旧主动能力，保留被动能力。

## 方案选择

采用“加载时完整编译、运行时纯原生枚举与执行”。

没有采用以下两种方案：

- 让 GDScript 每个节点枚举主动行动、C++ 只执行，会保留跨语言和字典遍历瓶颈；
- 让 C++ 现场解释原始 `Dictionary` 主动声明，会违背紧凑状态与编译声明池的目的。

## 编译表示

新增 `CompiledActivation`，由 `CompiledAbility` 持有：

- `target_rule`：八种目标规则的枚举值；
- `required_ki`：把所有合法 `spend_ki` 费用累计后的结果；
- `costs`：编译后的费用动作列表，用于产生与 oracle 相同的内力事件及连锁；
- `actions`：编译后的主动效果动作列表；
- `declaration_valid`：目标、费用或动作声明无法编译时为假。

`CompiledAbility.has_activation` 不再只是布尔占位，而由非空、有效的编译主动声明派生。
运行时卡牌仍只保存有序能力条目和稳定句柄，不复制声明树。

## 原生入口

内核增加两个测试入口：

1. 枚举当前状态的合法行动，输出足以重建 `DuelAction` 的纯数据；
2. 根据来源格、来源实例 ID、目标种类、目标索引和主动能力索引执行主动行动。

行动顺序必须与 `DuelSimulator.get_legal_actions()` 相同：

1. 普通手牌出牌仍先按手牌逻辑顺序和棋盘格顺序生成；
2. 若存在待用额外出牌，不生成任何主动行动；
3. 否则按棋盘 `0→8` 扫描当前方卡牌；
4. 每张牌按当前有效主动能力数组顺序扫描；
5. 每个主动能力按其目标规则的既有顺序生成目标。

本阶段也提供原生的“某一方是否至少有一个合法行动”精确查询，使终局和空回合推进不再
依赖“牌上存在主动能力”这一粗略近似。

## 目标规则

棋盘相邻目标使用上、右、下、左顺序。任意棋盘目标与“其它友方”使用格子 `0→8`。
手牌目标使用该方逻辑手牌数组 `0→n-1`，不使用视觉节点顺序。

规则如下：

- `adjacent_empty_board`：相邻且为空；
- `adjacent_ally_board`：相邻且当前所属方相同；
- `adjacent_enemy_board`：相邻且当前所属方不同；
- `other_ally_board`：全场除来源外的当前友方；
- `ally_hand_card`：来源当前所属方的手牌；
- `enemy_hand_card`：来源当前所属方之敌方的手牌；
- `any_empty_board`：全场任意空格；
- `any_enemy_board`：全场任意当前敌方。

来源必须仍在指定格、实例 ID 相同、属于当前行动方且效果门控启用。费用不足或目标集合
为空时，不生成主动行动。

## 执行事务

执行主动行动时，在私有原生分支上重新验证：

1. 当前没有待用额外出牌；
2. 来源格、来源实例和当前所属方匹配；
3. 主动能力索引在当前有效主动能力列表中仍然有效；
4. 累计内力费用可支付；
5. 目标种类和索引仍符合当前目标规则。

验证通过后：

1. 记录能力来源和指定目标的不可变实例快照；
2. 发出 `ability_activated`；
3. 按声明顺序执行费用动作；
4. 按声明顺序执行主动效果动作；
5. 立即完整处理动作引发的攻击、进场、翻面、移动、弃牌、抽牌和其它事件；
6. 对棋盘或手牌指定目标，全场发现并结算 `card_after_targeted_activation`；
7. 把全部额外出牌请求交给共用 `finish_action`；
8. 进入共用回合结束、空回合和终局边界。

主动过程中来源可以移动、交换、翻面或离场。后续动作使用既有实例快照和卡牌引用规则：
要求当前实例仍存在的动作会重新定位；声明允许使用初始格的动作继续使用快照；失效上下文
按声明的 `on_invalid_context` 决定跳过还是停止该规则。

## 新增动作衔接

当前主动声明还会到达三种尚未用于现有原生手牌出牌路径的动作：

- `move_self_to_target`：使用指定棋盘格，经全场 `card_before_moved`、`card_moved`、
  `card_after_moved` 事务移动能力来源；
- `swap_self_with_target`：锁定指定棋盘实例，按 oracle 的两段移动顺序交换，并在每一段
  之间重新验证。
- `reveal_card`：按指定观察者更新目标实例的公开顺序，并只在首次公开时发出规范
  `card_revealed` 事件；目标可以位于手牌，不能依赖棋盘格。

移动与交换应复用既有移动函数，不能复制移动或减点移除逻辑。`activation_target` 格子引用在
生成进场中读取本次主动指定的棋盘格。

## `card_after_targeted_activation`

仅当动作目标种类是 `board_cell` 或 `hand_slot` 时发送。事件上下文包含：

- 发动者实例 ID；
- 发动时所属方；
- 结算主动效果后重新定位得到的来源格，离场则为 `-1`；
- 原始目标种类和目标索引。

事件发现扫描当前全场并按格子顺序锁定触发组；每组在执行前继续使用稳定能力句柄和当前
来源状态重验。主动目标不会因结算中手牌压缩或棋盘变化而改成另一个目标。

## 失败和原子性

- 调用时已非法的行动返回 `valid = false`，不修改已加载根状态；
- 到达未编译声明时返回 `supported = false`；
- 所有失败都不返回部分 payload、事件、翻面或移除结果；
- 不为具体卡牌 ID 添加分支；
- 目录中未被当前事务到达的未来声明不影响该行动。

## 测试

原生探针增加以下覆盖：

- 八种目标规则的目标顺序、过滤和空目标；
- 费用不足、多个费用累计、多个主动能力索引和效果门控；
- 动态主动能力替换、能力删除或换位后的索引语义；
- 额外出牌期间禁止主动能力；
- 来源或目标在行动生成后失效；
- 有凤来仪的移动、友方交换和敌方交换；
- 寒冰真气的敌方手牌减点与揭示；
- 燃木刀法、无相劫指的指定友方手牌弃置；
- 梯云纵的双方重新进场与新实例耗内力；
- 剑法精要的移动和额外出牌；
- 三环套月的移除区实例复活与照常抽牌；
- 大魁星的指定加点和群体攻击；
- 雁回祝融的友方回手和新复制进场；
- `card_after_targeted_activation` 的全场顺序、来源移动和来源离场；
- 主动行动后的结束节点、额外出牌、空回合与终局。

对真实 Quick 派生状态建立主动行动语料。对每个 oracle 合法主动行动比较：

- 完整规范状态键；
- `state_version`；
- captures；
- exiles；
- 完整事件数组及顺序。

实现过程中每个阶段运行原生探针。全部主动能力完成后运行仓库完整套件，并记录：

- 真实语料主动行动总数；
- 原生支持数、精确一致数和拒绝原因；
- 原生主动事务与 oracle 的 Debug 吞吐对比。

## 完成标准

- 当前牌库所有主动声明可编译；
- 固定真实语料中所有合法主动行动均原生支持且精确一致；
- 现有 490 个 Quick 根手牌出牌继续零差异；
- 原生探针、完整测试套件全部通过；
- 文档明确原生内核仍为测试专用，尚未接入生产搜索。

## 后续边界

主动事务完成后，下一阶段才是原生搜索试验：根状态转换一次、整棵试验树保持紧凑原生、
最终选中结果转换回来一次。该阶段必须单独验证动作枚举、评分、完整轮次深度、确定性和
超时行为，不能因主动事务完成就直接切换生产路径。
