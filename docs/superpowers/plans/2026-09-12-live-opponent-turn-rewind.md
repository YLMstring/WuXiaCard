# 对局内悔棋与对手回放实施计划

依据：`docs/superpowers/specs/2026-09-12-live-opponent-turn-rewind-design.md`

## 1. 固化检查点契约

- 扩展 `tests/test_duel_undo.gd`，先覆盖玩家同一回合额外出牌不覆盖首次决策前检查点。
- 在 `scripts/duel_controller.gd` 以回合为边界捕获玩家检查点，而不是每次玩家行动都覆盖。
- 保持检查点的状态、整局回放动作数量和熟练度候选列表一起恢复。

## 2. 记录并验证对手回合

- 增加独立的对手回合检查点：完整状态、整局回放截断位置和本回合实际动作数组。
- 对手第一次合法决策建立检查点；主动能力与额外出牌均追加动作，但不覆盖检查点。
- 在实际回滚前，用检查点副本通过 `DuelSimulator` 预演全部动作；任一动作不合法或结算失败时保持当前局面不变。

## 3. 接入按钮与视觉回放

- 对局结束时保留现有整局回放入口。
- 正常对局只有玩家决策状态响应按钮：先尝试悔棋，失败后再尝试对手回放。
- 对手回放恢复检查点、截断整局动作记录，并按记录顺序重新提交原动作，不启动 AI 搜索。
- 每个动作执行前等待 `replay_turn_delay`（生产值两秒），期间锁住交互并显示“回放中...”。
- 回放结束后恢复玩家决策状态和正常提示；对手回放期间及其它非玩家决策状态按键无效。

## 4. 回归测试与文档

- 扩展 `tests/test_duel_undo.gd`，覆盖普通出牌、主动能力、双方额外出牌、悔棋失败后的后备回放、等待提示和无效时机。
- 回归 `test_duel_replay.gd`，确认整局回放入口与节奏不变。
- 更新 `docs/HANDOFF.md`、`docs/ARCHITECTURE.md`、`docs/DECISIONS.md` 与 `docs/TESTING.md`。
- 运行相关测试和完整套件，并以静音方式检查正常对局中的按钮流程。

## 5. Android Release

- 检查 Android 预设、主场景、版本和现有签名配置。
- 运行仓库的 `tools/build_android_release.ps1`；该脚本负责构建 ARM64 原生库并导出 Release APK。
- 检查产物存在、更新时间、大小以及 APK 内 ARM64 原生库条目。
