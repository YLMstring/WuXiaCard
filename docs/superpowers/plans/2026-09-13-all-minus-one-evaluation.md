# 四边负一点牌静态评估实施计划

日期：2026-09-13  
设计：`docs/superpowers/specs/2026-09-13-all-minus-one-evaluation-design.md`

## 工作规则

- 原生搜索仍是唯一生产搜索路径，搜索保持卡牌 ID 无关。
- 只改变四边全部为 `-1` 的单牌资源估值，不改变规则、排序、状态键或终局计分。
- 完整套件只在行为改动完成后运行一次；聚焦测试和基准均使用 Dummy 音频。
- 先保留完全匹配当前提交的 Release 原生库，再修改搜索热路径。
- 基准 DLL、日志和 JSON 保存在 `.summer/local/`，不提交。

## 任务一：保留性能基线

1. 记录当前提交与工作区状态。
2. 以 Release 优化配置构建 Windows `template_debug` 原生库，使其可被无界面
   Summer Engine 基准加载。
3. 保存该 DLL、源码提交号、文件哈希和构建参数到 `.summer/local/`。
4. 在新版本完成后交换同一加载位置中的旧、新 DLL，使用相同固定局面交错测速。

## 任务二：先写评估回归测试

修改 `tests/test_native_production_rules.gd`：

1. 构造只相差根方手牌点数的非终局状态。
2. 证明 `[-1, -1, -1, -1]` 与 `[6, 6, 6, 6]` 的新评估相同。
3. 证明 `[-1, 6, 6, 6]` 仍按真实点数和计算。
4. 为 112 局实验增加临时的“恢复旧负四点评估”搜索限制，并断言生产默认不恢复旧值。

## 任务三：实现通用代理值

修改原生搜索的单牌资源价值计算：

1. 在现有四边循环中同时累计真实点数并检测是否四边全为 `-1`。
2. 全为 `-1` 时加 `24`，否则加真实总和。
3. 不增加目录查询、区域扫描、动态分配或卡牌 ID 判断。
4. 临时旧评估限制只服务聚焦测试与同进程 A/B 赛程；生产默认固定为新评估。

构建原生库并运行 `test_native_production_rules.gd`、`test_duel_search.gd`。

## 任务四：验证性能和完整套件

1. 用保留的旧 DLL 与新 DLL交错运行相同 Release 固定深度局面。
2. 比较评分、动作、节点数、耗时和节点吞吐；评分/动作允许因评估目标本身而改变，
   但同版本重复运行必须确定。
3. 若有可重复的额外热路径开销，立即报告。
4. 运行 `tools/run_tests.ps1` 完整套件。

## 任务五：运行 112 局固定深度对照

1. 为 AI 基准增加临时评估变体：实验席使用新代理，对照席恢复旧评估。
2. 使用进阶 0 的 Extended 28 组配对、四局换边赛程。
3. 双方固定 `self_turn` 深度 2，无时间或节点上限，PV、History 与 8 MiB TT 相同。
4. 每局立即输出并写入 `.progress.jsonl`，最终校验 112 局完整、无重复、无非法
   行动、无 fallback 且全部决策达到深度 2。
5. 汇总得分率、分差、先后手/卡组分项、节点和耗时，由结果决定是否保留新评估。

## 任务六：定案与清理

若采用新评估：

- 删除临时旧评估开关与基准变体，只保留生产新逻辑和永久回归测试；
- 更新 `docs/AI_SEARCH.md`、`docs/TESTING.md` 与 `docs/HANDOFF.md`；
- 重建原生库并复跑受清理影响的聚焦测试。

若否决新评估：

- 回退代理值逻辑与临时开关；
- 在设计文档记录实验结果，保留基准报告但不提交生成物。

## 完成标准

- 四边全部为 `-1` 的牌只在静态评估中等价于四边 `6`。
- 部分负数、实际规则、结构排序、终局计分和状态键不变。
- 完整自动化套件通过。
- 112 局报告有效、完整，并足以支持是否接入生产的决定。
