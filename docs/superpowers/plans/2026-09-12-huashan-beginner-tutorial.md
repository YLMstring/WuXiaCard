# 华山进阶零新手教程实施计划

依据：`docs/superpowers/specs/2026-09-11-huashan-beginner-tutorial-design.md`

## 1. 先建立存档状态契约

- 在 `tests/test_deck_profile_store.gd` 增加教程状态测试：
  - 默认档与迁移后的旧档均为未等待教程；
  - 成功创建“华山派、进阶零”新轮后标记为等待教程；
  - 其他门派或其他进阶的新轮不产生标记；
  - 完成教程后原子保存为已完成；
  - 保存失败时保留原状态，不能误判为已经看完；
  - 闭关重修、通关重置和归隐后该轮状态被清除。
- 在 `scripts/deck_profile_store.gd` 将存档版本升至下一版，加入严格布尔字段
  `tutorial_pending`，并提供只读查询与“完成教程并保存”的窄接口。
- `begin_run_and_save()` 根据最终选定的门派和难度设置该字段，不由界面层
  重复推导。字段为 `true` 时必须同时满足：本轮有效、门派为华山派、难度
  为零。
- 旧版存档迁移时固定补为 `false`，避免已经进行中的旧轮次突然显示教程；
  默认档、重置后的档案同样为 `false`。

## 2. 建立独立教程场景

- 新建 `scripts/tutorial_controller.gd`：
  - 进入教程时一次性加载 `res://pics/tutorial/tutorial_01.png` 至
    `tutorial_10.png`，退出教程后不再持有这些高分辨率纹理；
  - 维护从零开始的当前页索引，进入场景即显示第一页；
  - 每次有效点击只前进一页；第十页后的点击只发出一次
    `completion_requested`；
  - 完成请求发出后暂时锁住输入，主流程保存失败时通过公开方法显示
    “保存失败，请重试”并重新允许点击；
  - 提供最少量调试查询，供测试读取当前页、当前纹理和完成请求状态。
- 新建 `scenes/tutorial.tscn`，节点保持纯 UI：
  - 根 `Control` 全屏铺开；
  - `TextureRect` 使用等比例居中覆盖，保证 `20:9` 完整显示、`16:9`
    上下居中裁切；
  - 铺满屏幕的透明 `Button` 统一处理鼠标和触屏释放，避免触摸事件与模拟
    鼠标事件各翻一页；
  - 单独的提示标签只在保存失败时显示，不改动教程图片本身。
- 新建 `tests/test_tutorial_scene.gd` 并加入 `tools/run_tests.ps1`：
  - 验证十张纹理顺序、一次点击一页、末页完成只发一次；
  - 验证长按、多点触控和重复释放不会连续跳页；
  - 在 `540×1200` 与 `540×960` 两种视口比例下检查图片保持比例、水平
    居中，以及后一种只发生上下裁切。

## 3. 把教程插入唯一主流程

- 在 `scripts/main_flow_controller.gd` 预载教程场景并新增 `_show_tutorial()`。
- 新增一个共同的“继续当前轮次”方法：重新读取存档，若
  `tutorial_pending` 为真则显示教程，否则显示组牌界面。
- 以下三条路径全部改走该共同入口：
  - 主菜单自动创建华山进阶零新轮成功后；
  - 门派选择控制器发出新轮创建成功信号后；
  - 重启游戏后从主菜单继续一个有效轮次时。
- 战后待领奖励仍保持现有优先级，不改变原有奖励恢复流程。
- 教程发出完成请求后，由主流程调用存档接口：成功才进入组牌界面；失败则
  留在第十页、显示提示并允许重试。
- 更新 `tests/test_main_flow.gd`：
  - 自动开始的华山进阶零先进入教程，完成后再进入组牌；
  - 门派选择创建的同组合走相同路径；
  - 中途销毁并重新实例化主流程后，从第一页恢复教程；
  - 完成后的同一轮再次从主菜单进入时直接到组牌；
  - 非华山或非进阶零不进入教程；
  - 更新原有假定“华山进阶零立即进入组牌”的断言与后续 fixture。

## 4. 接入现有音乐上下文

- `_show_tutorial()` 显式调用
  `MusicDirector.request_context(MusicDirector.CONTEXT_MENU)`，不新增教程音乐
  上下文，也不请求 `CONTEXT_STORY`。
- 保持 `scripts/music_director.gd` 的现有同池续播逻辑不变：若当前菜单曲仍在
  播放，请求菜单上下文只更新上下文，不换曲、不重播。
- 教程完成后复用 `_show_deck_builder()`，由它首次请求 `CONTEXT_STORY`，
  从菜单曲淡出后进入既有 `village/story` 池。
- 扩展 `tests/test_music_flow.gd`：
  - 主菜单进入教程后仍是菜单上下文；
  - 当前曲目路径、已启动曲目数量均不变化；
  - 教程期间一首曲自然结束后仍从菜单池选曲；
  - 完成教程进入组牌后才切换到故事上下文。

## 5. 分层验证与实机检查

- 先运行教程场景、存档、主流程和音乐专项测试，修正新增契约导致的既有
  fixture 变化。
- 运行完整套件：

  ```powershell
  powershell -ExecutionPolicy Bypass -File tools/run_tests.ps1
  ```

- 使用静音方式启动游戏，不修改正常音频默认值，实际走完：
  - 自动开始华山进阶零；
  - 门派选择开始华山进阶零；
  - 教程中途退出并重新进入；
  - 看完十页后进入组牌。
- 分别以 `540×1200`（`20:9`）和 `540×960`（`16:9`）纵向视口检查十页，
  确认前者完整显示，后者上下居中裁切且关键信息可读。
- 检查鼠标单击和触屏事件模拟均为一次一页；若连接的 Android 设备可用，
  再进行一次不出声的真机触摸检查。此次计划不自动导出发行包。

## 6. 文档与提交收尾

- 更新 `docs/HANDOFF.md`、`docs/UI_AND_ANDROID.md` 和必要的
  `docs/DECISIONS.md`，记录教程触发条件、持久化字段、场景入口及菜单音乐
  归属。
- 检查工作树，只纳入教程功能及相应测试、文档和十张已确认图片，不修改或
  提交无关用户文件。
- 提交前执行 `git diff --check`，报告完整测试、视觉验收和真机检查结果，
  明确仍未执行的 Android 导出事项。
