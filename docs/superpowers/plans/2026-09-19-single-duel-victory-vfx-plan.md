# 单场战斗红金徽章胜利特效实施计划

## 目标

按照 `docs/superpowers/specs/2026-09-19-single-duel-victory-vfx-design.md`，把当前约 `1.3` 秒的“金色胜字＋水墨爆散”替换为四秒红金徽章演出：图像模型生成包含祥云和书法“胜利”双字的完整透明主体，程序控制砸落、回弹、暗角、闪光、放射光和金色粒子。

真实对局首次胜利时播放；`1.10` 秒开放获胜比分和“打道回府”，玩家可以立即离场；无人操作时特效在第 `4.00` 秒自然结束。回放抵达胜利终局时不播放特效。

## 当前基线

- 当前实现文件为 `scripts/victory_vfx.gd`、`scenes/victory_vfx.tscn`、`scripts/duel_controller.gd` 和 `tests/test_duel_outcome.gd`。
- 当前水墨版本已经通过聚焦终局测试、完整 `84/84` 自动测试和静音实机预览；自该结果后相关行为代码没有变化，因此代码修改前复用这份基线，不重复运行完整套件。
- 开始每一阶段前检查 `git status --short`，只处理本计划涉及的文件。

## 1. 生成并确认主体素材

目标文件：

- `art/vfx/victory_emblem.png`

步骤：

1. 使用图像模型生成 `1536×1536` 透明主体图，完整包含原创红金圆形徽章、向左右展开的祥云和错落排布的金色书法“胜利”双字。
2. 提示词明确排除背景、放射光、粒子、水墨、水印、额外文字和被裁切的祥云。
3. 单独检查透明通道、构图留白，以及“胜”“利”两个汉字的笔画和可读性。
4. 把候选图展示给用户；文字错误或风格不合适时直接编辑或重新生成，不使用标准字体替换。
5. 用户确认候选图后才复制到运行时路径并开始代码接入。

这一阶段是独立视觉检查点，主体图未获确认前不修改运行时代码。

## 2. 先更新终局行为测试

修改：

- `tests/test_duel_outcome.gd`

覆盖以下行为：

1. 真实胜利立即启动一次特效，并在稳定时点前隐藏比分与归程按钮。
2. 新增不依赖真实等待的调试稳定入口；触发后特效仍在播放，但比分和“打道回府”已经可见。
3. 稳定前顶部退出和归程操作均不能离场。
4. 稳定后点击“打道回府”立即发出一次胜利结果，并安全取消剩余特效。
5. 玩家不离场时，调试完成入口结束特效，但不会重复显示控件或重复发出结果。
6. 回放状态抵达胜利终局时不增加特效播放次数；回放退出播放状态后正常显示最终控件。
7. 失败终局继续直接显示现有控件，不启动特效。
8. 重复终局检查和重复归程输入不会叠加演出或重复发出结果。

先运行聚焦测试，确认新增断言会针对旧行为失败，再开始实现。

## 3. 重建 `VictoryVfx` 表现层

修改：

- `scenes/victory_vfx.tscn`
- `scripts/victory_vfx.gd`

场景层级替换为：

- 全屏输入拦截层；
- 暖黑 `Dimmer` 与 `Vignette`；
- `RadialGlow`；
- 可旋转的 `LightRays`；
- `VictoryEmblem` 主体图片；
- `ImpactFlash`；
- 限量 `GoldParticles`；
- 现有 `GongPlayer`。

脚本改动：

1. 新增 `settled` 信号，在 `1.10` 秒主体稳定显现时只发出一次。
2. 保留 `finished` 信号，在 `4.00` 秒自然结束时发出一次。
3. 动画按设计分为进入、砸落、收光、停留、淡出五段；锣声移到落定时点，不再在 `play()` 开始时立即播放。
4. `cancel()` 必须终止 tween、粒子和音频，并使本次尚未执行的稳定及完成回调失效；取消不发送 `settled` 或 `finished`。
5. 提供 `complete_settle_immediately()` 与 `complete_immediately()` 调试入口，让测试无需等待真实四秒。
6. 缺少主体纹理时启用仅用于故障降级的实时金色“胜利”文字，仍按相同时序发信号。
7. 粒子使用局部一次性发射器，数量受限；演出结束后不保留 `_process()` 工作。

不增加通用特效框架，不修改模拟器或原生规则。

## 4. 接入提前归程与回放旁路

修改：

- `scripts/duel_controller.gd`
- `scenes/duel.tscn`

步骤：

1. 控制器连接 `VictoryVfx.settled` 和 `VictoryVfx.finished`。
2. 增加仅描述表现阶段的布尔状态，区分“特效正在播放”与“主体已经稳定、允许归程”。
3. `_sync_terminal_hand_action()` 在真实胜利稳定前隐藏玩家手牌区和归程按钮；稳定后即使特效仍在播放，也显示归程按钮。
4. 稳定时把比分和归程按钮放到特效输入拦截层之上；其它按钮、卡牌检查和回放操作继续位于拦截层之下。
5. 为归程按钮使用独立处理入口。稳定后点击它时先取消特效、清除表现状态，再复用现有胜利离场逻辑；顶部退出按钮在特效播放期间继续不可用。
6. 正常四秒完成时只清理表现状态和层级，不重复执行终局逻辑。
7. `_finish_match()` 在 `_is_replaying` 为真时直接绕过胜利特效。完整回放收尾恢复 `_is_replaying = false` 后，现有同步逻辑立即显示最终比分和归程按钮。
8. 场景退出、重建、取消回放和控制器释放路径统一调用特效取消逻辑，避免旧 tween 或信号访问已经离开的场景。

## 5. 清理旧水墨资源

检查：

- `art/vfx/victory_ink_burst.png`
- `art/vfx/victory_ink_burst.png.import`

使用 `rg` 确认新场景接入后仓库中没有其它引用，再删除旧水墨源图。Godot 生成的导入缓存不手工提交；只处理仓库追踪的源资源和相应追踪元数据。

## 6. 聚焦验证与视觉调整

1. 运行 `tests/test_duel_outcome.gd`，确认所有终局行为断言通过。
2. 执行无头资源导入，确认新透明 PNG 正确生成导入数据且没有资源加载错误。
3. 静音启动真实对局胜利预览，检查 `540×960`：主体位置、祥云安全边距、闪光强度、文字可读性、`1.10` 秒控件层级和 `3.00–4.00` 秒淡出。
4. 使用真实短屏窗口复查整体缩放，不能裁切祥云或遮住归程按钮。
5. 分别走查：等待完整四秒、`1.10` 秒后立即归程、失败终局、胜利回放终局无特效。
6. 检查运行诊断；任何素材错误、脚本错误或重复信号都必须修复后再继续。

视觉参数只在本阶段根据实际画面微调，不改变已经确认的触发规则和四秒时序。

4. 提交实现；本轮不导出 Android APK，除非用户另行要求。
