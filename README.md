# 九宫论剑

《九宫论剑》是一款武侠题材的单人九宫格卡牌游戏。你要从手牌中打出招式牌，用卡牌四边的点数进攻相邻敌牌，把它们翻成己方颜色，并在一轮轮战斗后调整牌组、解锁门派与更高阶武学。

游戏采用竖屏布局，鼠标和触屏都可以操作。规则的骨架很简单：**放下一张牌，看两边相对的点数；攻击边更大，就把对面的牌翻成自己一方**。真正的变化来自每张武学牌的能力、触发时机和组合方式。

## 三分钟看懂怎么玩

### 1. 你要做什么

棋盘共有 9 个格子。双方轮流把牌放进空格，或发动场上卡牌的主动能力。你的目标是让棋盘上属于你的牌比对手多。

卡牌被攻击成功后通常不会消失，而是会**翻面**：它留在原位，但归攻击方所有，颜色也随之改变。于是同一张牌可能在一局中多次易主。

### 2. 四边点数怎么看

每张普通卡牌有上、右、下、左四个点数：

```text
       上
    左 牌 右
       下
```

把牌放下后，它会尝试攻击符合条件的牌。攻击相邻牌时，只比较两张牌互相面对的那一边。

例如：你把一张“右边为 5”的牌放在敌牌左侧，而敌牌“左边为 3”，那么 `5 > 3`，敌牌会翻成你的颜色。若双方点数相等，普通情况下不会翻面。

### 3. 每回合做一件事

轮到你时，通常二选一：

- 从手牌拖一张牌到空格；
- 点击有主动能力且内力足够的己方场上牌，选择合法目标发动能力。

有些能力会让你额外出牌。额外出牌仍在同一个回合内完成，只能出手牌，不能改为发动主动能力。

### 4. 内力是什么

卡牌上的圆珠表示内力。发动主动能力通常消耗 1 点内力。内力和卡牌能力是两回事：卡牌翻面后，内力仍会保留；能力则通常会失去，除非牌面规则明确说它会保留。

### 5. 什么时候结束

最常见的结束方式是棋盘填满。部分能力会在终局前把牌移走，所以“刚刚填满”不一定立刻结束；相关能力结算完后，如果棋盘仍满，才按双方在场牌数计分。

游戏也会在行动达到上限，或同一棋盘局面出现 5 次时结束。所有终局判断都放在当前回合完整结束后、下一个回合开始前进行。

<a id="first-run"></a>
## 第一次游玩指引

### 1. 从主菜单开始

开始新一轮闯关后，先选择一个已经解锁的门派。普通模式初始可选华山派；击败声明了门派的敌人后，可以逐步解锁其它门派。

每轮闯关还会记录一个难度。新存档最初只能选择难度 0；通关难度 `n` 后解锁难度 `n + 1`，最高为 9。解锁多个难度后，可用门派卷轴左右两侧的箭头循环选择；选择会立即保存。当前版本暂不为进阶难度添加实际战斗效果。

“闭关重修”会结束当前闯关，清掉本轮解锁的卡牌、当前主卡组和本轮实际难度，但保留已经解锁的难度与上次难度选择，也保留门派、各门派最高分和卡牌精通。“封剑归隐”是完整重置，会连这些长期进度一起清除。

### 2. 选门派后会拿到什么

普通模式开局固定拥有：

- 太祖长拳；
- 1 阶吐纳术；
- 所选门派的全部 1 阶牌；
- 另外随机解锁的 3 张 1 阶牌。

开局主卡组由太祖长拳、1 阶吐纳术和那 3 张随机牌组成。测试模式会临时解锁全部卡牌，但不会把这些临时解锁写入普通存档。

### 3. 在组牌界面准备 5 张牌

主卡组必须正好有 5 张牌，它们就是下一场战斗开始时的 5 张手牌。玩家主卡组不能放入两张同名武学，即使它们等级或卡牌编号不同。

在牌库中点击卡牌可以查看说明；按住并拖动可以与主卡组交换。组牌时先保证四边点数覆盖不同方向，再考虑能力配合。全是高阶牌不一定最好：低阶牌可能更容易摆放，也可能正好补足某个方向。

### 4. 进入战斗

先后手确定后，**后行动的一方**会在两个随机且相邻的空格中拥有两张“八卦方位”。它们是开局场面的一部分，不触发进场能力，也不会进行进场攻击。

轮到你时，把手牌拖到发亮的空格。想发动主动能力时，先点击场上有内力的己方牌，再选择目标。点一下已经揭示的牌，可以在卷轴中查看它的固定卡牌说明。

### 5. 打完一局以后

胜利和失败都会记作一次有效对局；中途退出不计。除最终通关或当前没有可选奖励等情况外，之后会进入随机三选一奖励，选中的牌加入你的收藏，可以在组牌界面换入主卡组。

胜利会提升本轮等级。到达 2、5、8、11 级时，会依次解锁所选门派的 2、3、4、5 阶牌。击败带有门派声明的敌人，还会永久解锁对应门派。

默认在取得 15 场胜利后通关。通关会像“闭关重修”一样清除本轮卡牌解锁和主卡组，但保留门派、最高分与精通记录。

### 6. 几条实用建议

- 不要只看最大的数字；先看你准备放在哪个格子，以及真正会用到哪一边。
- 角落只接触两个相邻格，中央会接触四个格。能力较安全的牌适合角落，想一次影响多张牌的牌更适合中央附近。
- 留意对手上一张打出的牌。战斗进行中，在双方行动之间按回放按钮，可以再次查看对手最近一次成功从手牌打出的牌。
- 有内力不等于一定能发动能力；还需要场上存在合法目标。
- 看不懂连锁结算时，先观察哪张牌发光、哪张牌先翻面。全场自动能力会按固定顺序结算，并不是随机发生。

<a id="rules-reference"></a>
## 具体结算规则

这一部分是规则查询表，说明所有卡牌共用的结算方式。单张卡牌的特殊文字仍以游戏内当前描述为准。

<a id="board-and-ownership"></a>
### 棋盘、方向与所有权

- 棋盘编号按从左到右、从上到下排列：

  ```text
  0 1 2
  3 4 5
  6 7 8
  ```

- 卡牌点数数组和界面方向的固定顺序是：上、右、下、左。
- “相邻”默认指上下左右正交相邻，不包含斜角。
- 每张运行中的牌都有唯一实例。两张同编号的牌也不是同一个实例；能力若锁定了某个实例，会继续跟踪那一张牌，而不是改找另一张同名牌。
- 卡牌同时记录“当前所属方”和“初始所属方”。翻面改变当前所属方，不会改写初始所属方。
- 场上颜色表示当前所属方。结算“友方”或“敌方”时，除非卡牌另有说明，都以结算当时的当前所属方为准。

<a id="hands-and-decks"></a>
### 手牌、主卡组与侧卡组

- 主卡组正好 5 张，它们构成开局手牌，不会同时再放进抽牌堆。
- 每一方都有自己的侧卡组。侧卡组根据该方实际主卡组中的门派和阶级生成，再独立洗牌；玩家是否已经收藏这些侧卡组候选牌不影响生成。
- 江湖牌不会为侧卡组提供同门派候选。
- 同名候选进入侧卡组时只保留最高阶版本；同阶冲突保留卡牌目录中靠前的版本。
- 双方开局的 5 张手牌分别独立洗牌，因此物理槽位顺序不等于组牌界面顺序。
- 手牌始终有 5 个固定槽位。抽牌和返回手牌会填入最左侧空位；普通出牌或从手牌移除会留下空位，不会让其它牌自动挤过去。
- 弃牌是例外：弃掉一张牌后，它右侧的手牌会同时向左平移一格。
- 侧卡组已空时，每次仍需抽牌都会生成一张新的太祖长拳；一次抽两张就会得到两张。

<a id="turns-actions-and-ki"></a>
### 回合、行动与内力

- 一个通常回合包含：确定行动方、结算该方回合开始能力、执行一次行动、结算该方回合结束能力、恢复本回合到期的临时效果，然后检查终局。
- 一次行动是“从手牌出一张牌”或“发动一次场上主动能力”。能力单纯授予额外出牌次数时，授予本身不增加行动数；真正打出每张额外牌时，各增加 1 次行动。
- 额外出牌次数可以叠加，必须在当前行动方的同一个回合内继续完成。额外阶段只允许出手牌，不能发动主动能力，也不会再次触发回合开始或回合结束节点。
- 若某方没有任何可用行动，不会跳过整个回合。该方的回合开始和回合结束能力仍会结算，只跳过行动阶段；这种空回合不增加行动数。
- 每次发动主动能力消耗 1 点内力。目标、费用和其它条件必须都合法，行动才可发动。
- 内力属于卡牌实例，卡牌翻面后仍保留。主动能力被替换或失去，不会自动清空内力。
- 卡牌获得新的主动能力时，会替换原有主动入口，但不删除与主动能力无关的被动效果。

<a id="play-and-summon"></a>
### 出牌与进场

普通从手牌出牌的大致顺序如下：

1. 锁定手牌中的确切实例与目标空格。
2. 结算该牌的“进场前”能力。
3. 将牌放入棋盘并记录本次成功出牌。
4. 按棋盘顺序结算全场的“有牌进场时”能力。
5. 按棋盘顺序结算全场的“有牌进场后”能力。
6. 若该牌仍在场上，且仍属于出牌方，发起它的标准攻击。

因此，若进场连锁使新牌离场，或让它在标准攻击前改变所属方，它不会继续进行原本的标准攻击。

“移动”不是“进场”。普通移动和交换位置不会重新触发进场能力，也不会天然获得一次标准攻击。八卦方位更特殊：它们直接存在于初始场面，连进场事件都不触发。

<a id="attack-and-flip"></a>
### 攻击与翻面

#### 标准攻击

- 普通标准攻击检查攻击者能攻击到的目标，并按规则确定目标顺序。没有距离能力时，通常只涉及正交相邻牌。
- 对正交目标，比较攻击者朝向目标的一边与目标朝向攻击者的一边。普通规则下，攻击点数严格大于防守点数才算合法；相等或更小都不攻击。
- 某些牌会改变距离、目标阵营、目标数量或点数比较方式。这些属于卡牌能力对通用攻击流程的修正。
- 只有至少找到一个在最初检查时确实可攻击的目标，才算真正发起攻击。点数不足、没有目标或已达到攻击次数限制时，不会触发“攻击后”一类效果。

#### 指定攻击

- 指定攻击由卡牌效果直接提出，仍使用同一套攻击与翻面流程。
- 指定的目标不会仅因为普通自动目标策略而改成另一张牌；只有效果明确声明目标修正时才会改变。
- 指定攻击若成功发起，也计入当前玩家本回合的攻击次数。

#### 一次攻击的时序

1. 在攻击开始时检查攻击者、目标、距离、阵营和点数，确认本次攻击最初合法。
2. 发出“攻击开始”，然后结算“被攻击时”能力。
3. 重新查找被锁定的确切攻击者和目标。若它们被移除、被替换，目标已不在仍然合法的攻击范围，攻击者已经变成另一方，或目标已属于预定翻面后的阵营，本次攻击结束。
4. 若仍可继续，结算“翻面前”能力。
5. 没有被阻止时，目标翻面并改变所属方。
6. 结算“翻面后”以及本次完整攻击之后的能力。

点数比较只在第 1 步进行一次。目标在“被攻击时”移动，不会要求重新比较新位置上的点数；当攻击已进入“翻面前”阶段后，普通移动也不会取消已承诺的翻面，系统会跟踪该确切实例到新位置。移除、替换、所属方变化或明确阻止翻面仍可使翻面无效。

多目标攻击逐个完整结算。若攻击者在其中一次连锁中翻面、从而改变所属方，它发起的这一轮后续攻击立即结束，不再继续寻找剩余目标。

为防止能力形成无限攻击循环，每一方每回合最多真正发起 20 次攻击。标准攻击、效果攻击和成功发起的指定攻击共用这个上限。

#### 翻面后的能力

- 卡牌能力默认在翻面时失去；只有目录中明确标记为“翻面保留”的能力会留下。
- 翻面先改变所有权，再移除旧的、非保留且不属于“自身翻面后触发”的能力。
- 旧的“自身翻面后触发”能力随后有一次结算机会，结算结束后也会失去。
- 在这次翻面后事件中刚获得的新能力不会被当成旧能力清掉。
- 已经永久失去的能力不会因为卡牌后来又翻回原所属方而恢复。

<a id="zones-and-movement"></a>
### 移动、弃牌、移除与返回

- **移动**：同一张实例从一个格子到另一个格子。成功移动会结算“移动前”和“移动后”节点，但不是进场。
- **交换**：视为两张确切实例依次完成各自的移动步骤；每一步都会重新检查位置与目标是否合法。
- **弃牌**：把确切手牌实例放入其当前所属方的弃牌区，并触发弃牌相关规则。弃牌不等于移除。
- **移除**：牌离开手牌或棋盘，进入其初始所属方的移除区。由四边点数都降到 0 引起的移除，也是真正的移除。
- **返回手牌**：能力可能把同一实例从场上或弃牌区放回指定一方的最左空手牌槽；手牌已满时，按该能力的声明处理，不能假定一定返回成功。
- **重新进场或复活**：有的能力移动原实例，有的能力生成一张全新的同编号实例。是否保留内力、已改变点数和临时状态，取决于能力声明的是“同一实例”还是“新实例”。
- 在手牌中的牌默认不会触发场上被动能力；只有能力文字或通用选择器明确包含手牌时才会参与。

<a id="abilities-and-timing"></a>
### 能力与触发顺序

- 游戏规则由事件节点驱动，例如回合开始、进场前、进场、进场后、攻击开始、被攻击、翻面前、翻面后、移动前、移动后、弃牌、移除前、移除后和回合结束。
- 全场能力按**棋盘格 0 到 8、能力在卡牌中的声明顺序、同一能力内的触发顺序**依次结算。手牌或其它区域的自动选择也使用声明好的稳定顺序，不依赖画面节点的先后。
- 一个触发能力一旦被接受，会先显示来源牌的触发反馈，再执行它声明的动作。主动能力不使用这一下自动触发反馈。
- 自动选择通常先按规则锁定候选实例，再逐张重查条件。前一张牌的完整结算可能改变后一张牌是否合法；非法目标会被跳过或停止当前规则，以该能力的声明为准。
- 若某个动作需要的牌已经离场、移动、被替换或不再满足条件，默认只有该动作无效，当前能力后面的其它动作仍会继续。只有明确声明“上下文无效时停止规则”的能力才会中断该能力剩余动作。
- 停止一条能力不会停止同一事件中的其它能力，也不会取消整个回合。
- 多张可见牌同时加减点时，逻辑事件仍按顺序发生，但画面会先共同停顿以展示旧点数，再并行播放变化动画。负数变化每边最低降到 0；正数变化没有通用上限。
- 四边同时变成 0 的普通点数牌会立刻移除。四边显示为 `-1` 的特殊牌不显示点数、可被任意非负点数攻击，也不能被加减点效果选中；主动指定它仍可发动并揭示，但点数变化本身无效，自动选择则会跳过它找下一个合法目标。

<a id="ending-and-score"></a>
### 终局与计分

终局统一在当前行动方的回合结束节点和临时效果恢复完成之后、下一个行动方的回合开始节点之前检查。

满足以下任一条件即可进入终局：

- 终局前能力结算完毕后，棋盘仍然填满；
- 已完成的行动数达到 100；
- 由每格“卡牌编号 + 当前所属方”组成的完整棋盘局面，第 5 次在回合边界出现；
- 双方都不再拥有任何合法行动。

达到 100 次行动时，不会截断当前玩家或敌人的回合。已经获得的额外出牌会继续完成，所以最终行动数可以超过 100。

终局按棋盘上双方当前拥有的牌数计分。玩家拥有的牌严格多于对手才算胜利；数量相同时按玩家失败处理。用于判断五次重复的场面不比较实例编号、点数、内力或能力，只比较 9 个格子中的卡牌编号和当前所属方。

闯关总分与单局棋盘分不同。默认通关时总分为：

```text
向下取整（15000 ÷ 有效对局数）
```

有效对局包括完成的胜利和失败，不包括中途退出。15 战全胜时为 1000 分；失败越多，最终分数越低。

<a id="information-and-replay"></a>
### 隐藏信息、记忆与回放

- 普通模式下，对手未揭示的手牌只显示牌背，不会泄露名称、说明或其它资料。测试模式会显示双方手牌，并允许手动控制双方。
- AI 规则计算使用完整状态，包括双方手牌和侧卡组顺序；隐藏只影响玩家看到的画面。
- 敌人会自动记住玩家带入战斗的 5 张主卡组牌，供需要这份信息的能力使用。
- 玩家会记住本轮已见过或已被打出的敌方武学名称；这些记忆可在之后的相关界面中显示，但不会把未揭示牌直接变成公开信息。
- 对局或回放正在进行时，回放按钮用于查看对手上一张成功从手牌打出的牌。它打开普通卡牌说明卷轴，不显示运行中的点数、内力或临时能力变化。
- 对局结束后，回放按钮会从完全相同的开局状态重新播放动作记录。回放复用正式结算与动画，不改变奖励、精通、敌人记忆或存档；普通模式下仍隐藏对手手牌。

<a id="progression-and-reset"></a>
### 闯关、奖励与重置

- 尚未开始闯关的基础存档只保留太祖长拳和 1 阶吐纳术。选择门派开始一轮后，才解锁该门派全部 1 阶牌与随机 3 张 1 阶牌，并组成初始主卡组。
- 每次完成胜利或失败都会增加有效对局数。只有胜利会推进等级、记录被击败敌人并提交本局获得的卡牌精通。
- 奖励为当前存档中的待领取三选一。领取后，所选卡牌进入收藏；未选的奖励不会自动加入牌库。
- 玩家等级最高为 15。跨过 2、5、8、11 级时，分别解锁所选门派对应的 2 至 5 阶牌。
- 难度范围为 0 至 9。通关当前难度后解锁下一难度；难度 9 封顶。本轮难度在开始闯关时锁定，普通胜负、奖励和重新打开游戏都不会改变它。
- 某张开局主卡组中的确切卡牌编号，只要其同编号手牌实例在胜利局中至少成功打出一次，就会获得精通。失败或中途退出不提交精通。
- 牌库和奖励中，已精通牌显示为蓝色，未精通牌显示为红色。卡牌名称颜色则表示阶级：1 阶浅灰、2 阶绿、3 阶蓝、4 阶橙、5 阶红；特殊阶级以牌面实际显示为准。
- “闭关重修”和正常通关都会清除本轮卡牌解锁、主卡组、当前等级、敌人进度、待选奖励与本轮实际难度，但保留最高已解锁难度、上次难度选择、已解锁门派、门派最高分和精通。
- “封剑归隐”恢复全新存档，连难度解锁、上次难度选择、门派解锁、最高分和精通也会清除。

<a id="technical-details"></a>
## 技术细节

### 环境与运行

- 引擎目标：Godot `4.6`，GL Compatibility。
- 已知可用组合：Summer Engine `0.5.54` / Godot `4.6.1.stable.mono.custom_build.3e132c1e2`。
- 主场景：`res://main.tscn`。
- 逻辑视口：`540 × 960`，竖屏，`canvas_items` 拉伸。
- Android 导出环境：JDK 21、Android SDK / Platform 36。当前包名和正式签名等发行配置仍需在发布前完成。

在 Summer Engine 或 Godot 中打开仓库根目录，运行 `main.tscn` 即可启动。

### 权威规则架构

人类操作、测试模式、贪心兜底和深度 AI 都走同一条规则路径：

```text
输入 / AI
   ↓
DuelAction
   ↓
DuelSimulator ──→ 新 DuelState
   │
   └────────────→ 纯数据事件 ──→ DuelController ──→ UI / 动画 / 音乐
```

- `DuelSimulator` 是唯一权威玩法实现，负责合法行动、攻击、能力、回合、终局和计分。
- `DuelController` 只负责把模拟器事件展示成卡牌、动画、音效和界面，不另写一套玩法判断。
- `DuelState` 与 `DuelAction` 只保存纯数据，不能引用场景节点、控件、补间动画或音频播放器。
- AI 使用带贪心兜底的迭代加深极小化极大 / Alpha-Beta 搜索。搜索保持卡牌无关，只依据通用点数、区域、所有权、内力、合法行动和能力结构评估状态。

### 主要文件

| 文件 | 作用 |
| --- | --- |
| `scripts/card_catalog.gd` | 卡牌资料、能力声明、实例创建与目录校验 |
| `scripts/enemy_catalog.gd` | 敌人资料、等级、卡组、门派与特殊声明 |
| `scripts/duel_decks.gd` | 双方开局手牌与侧卡组构造 |
| `scripts/duel_state.gd` | 棋盘、手牌、区域、回合和运行状态 |
| `scripts/duel_simulator.gd` | 权威对局结算与通用规则流程 |
| `scripts/duel_ability_executor.gd` | 通用能力动作、费用、选择与状态修改 |
| `scripts/duel_controller.gd` | 正式对局场景、输入和事件演出 |
| `scripts/deck_profile_store.gd` | 存档、难度、解锁、奖励、精通、闯关和最高分 |
| `scripts/main_flow_controller.gd` | 主菜单、选门派、组牌、对局、奖励与结局流程 |
| `scripts/music_director.gd` | 跨界面音乐池、续播、淡出与特殊曲目 |

存档默认位于 `user://wuxia_deck_profile.json`。它带版本号，加载时会校验并尽量修复旧数据；写入采用临时文件替换，避免只保存一半。

### 测试

Windows 下的完整测试命令：

```powershell
powershell -ExecutionPolicy Bypass -File tools/run_tests.ps1
```

找不到引擎时可以指定路径：

```powershell
powershell -ExecutionPolicy Bypass -File tools/run_tests.ps1 `
  -EnginePath "C:\path\to\Summer.exe"
```

测试覆盖卡牌目录、敌人目录、存档与奖励、组牌界面、规则、权威模拟器、AI 搜索、对局集成、回放、音乐和各组卡牌能力。玩法或视觉改动不能只看脚本能否编译；提交前还应在 `540 × 960` 竖屏中实际走完受影响流程。Android 专属问题需要设备或 Android 构建验证。

### 当前范围

当前项目已经包含单人闯关、门派选择、收藏与组牌、奖励、卡牌精通、AI 对战、回放、结局和背景音乐。它仍是开发中的游戏项目，不包含联网对战，也尚未完成正式 Android 发布所需的包名、签名和商店材料。
